## Mục tiêu
Code ứng dụng không thể đọc/ghi dữ liệu tenant mà quên `tenantId`: `forTenant(db, tenantId)` trả repository đã gắn
tenant cho mọi bảng nội dung; client Prisma từ `createDb()` ném lỗi khi query model tenant không có tenant; ESLint cấm
import Prisma/`pg`/client sinh ra ngoài `packages/db`.

## Thiết kế

### 1. Guard thiếu tenant trong client (`src/tenantScope.ts`)
- Hàm thuần `assertTenantScoped(model, operation, args)`; `createDb` gọi trong cùng `$allOperations` với
  `assertNoCrossTenantConnect`. Ném `MissingTenantError extends Error` (export) với `model`, `operation`.
- Ném ở **mọi môi trường** (chặt hơn "dev/test" của story: thiếu tenant là bug lập trình; 500 tốt hơn rò dữ liệu).
- `tenantModels` = bảng có `tenantId` bắt buộc (danh sách trên). `schema.test.ts` thêm kiểm: mọi model có trường
  `tenantId` nằm trong `tenantModels` hoặc `optionalTenantModels` (Outbox, AuditLog); model không có `tenantId` thì
  không nằm trong hai danh sách.
- "Có tenant" nghĩa là:
  - `where`: `where.tenantId` là chuỗi, `{ equals: chuỗi }` hoặc `{ in: chuỗi[] }` không rỗng; hoặc một khóa unique
    ghép `where.tenantId_<…>` có `tenantId` là chuỗi.
  - `data` khi tạo: `data.tenantId` chuỗi hoặc `data.tenant.connect.id` chuỗi; `createMany*`: mọi phần tử đều có.
- Áp cho thao tác: `findMany, findFirst(OrThrow), findUnique(OrThrow), count, aggregate, groupBy, update, updateMany(AndReturn),
  delete, deleteMany` → kiểm `where`; `create, createMany(AndReturn)` → kiểm `data`; `upsert` → kiểm cả `where` và
  `create`. `optionalTenantModels`: chỉ bắt buộc **có khóa** `tenantId` trong where/data (cho phép `null` = việc nền tảng).
- Raw (`$queryRaw*`, `$executeRaw*`) trên client có guard → ném `MissingTenantError` (truy vấn raw đi qua client nền
  tảng nội bộ nếu sau này cần). Không đụng model nền tảng (Plan, Tenant, User, PlatformAdmin) — nested write dưới
  `Tenant` đã do `assertNoCrossTenantConnect` kiểm.
- Thứ tự trong extension: kiểm tenant trước, rồi cross-tenant connect.

### 2. Repository (`src/repository.ts`)
```ts
export type DbClient = Db | Prisma.TransactionClient-tương-đương-của-Db; // tx trong db.$transaction(async tx => …)
export function forTenant(db: DbClient, tenantId: string): TenantRepo;
// TenantRepo: một khóa cho mỗi bảng tenant bắt buộc, tên = delegate Prisma:
//   site, page, pageVersion, sectionContent, domain, media, lead, leadIntegration, membership,
//   product, productCategory, project, story, post, faq, testimonial, branch, certificate, brand, pressItem, service
// Mỗi repo:
//   list(args?)   → findMany({ ...args, where: { ...args?.where, tenantId } })
//   first(args?)  → findFirst(tương tự)
//   get(id)       → findFirst({ where: { id, tenantId } })  (null nếu của tenant khác)
//   count(args?)  → count(tương tự)
//   create(data)  → create({ data: { ...data, tenantId } })          // data: unchecked input bỏ tenantId
//   update(id, data) → updateMany({ where: { id, tenantId }, data }) → { count }   (B → 0)
//   delete(id)    → deleteMany({ where: { id, tenantId } })          → { count }   (B → 0)
```
- `tenantId` đặt **sau** spread nên caller không ghi đè được; `OR`/`AND` của caller vẫn nằm trong cùng mức với
  `tenantId` (Prisma AND các khóa cùng cấp). Kiểu đầu vào bỏ `tenantId`/`tenant` (`Omit<…>`); runtime cũng xóa hai khóa
  này khỏi `data` trước khi gắn.
- Không thêm phương thức nào khác (không `upsert`, không `findUnique`) — story sau thêm khi cần, cùng quy tắc.
- Một helper generic dựng repo cho mọi delegate; kiểu dựa trên `Prisma.<Model>Delegate`/`Prisma.Args` — không viết tay
  21 lớp. `tenantId` không phải UUID hợp lệ → `forTenant` ném lỗi ngay.
- **Ghi có kiểm tham chiếu JSONB**: `create`/`update` gọi `assertRefsBelongToTenant(db, tenantId, refs)` **trước** khi
  ghi, với `refs` rút từ JSON:
  - `sectionContent`: `data` và `draftData` theo `sectionRegistry.getType(type).schema` (type lấy từ `data.type`; với
    `update` không có `type` → đọc `type` của bản ghi trong tenant; không thấy bản ghi → `{ count: 0 }`, không ghi).
  - collection có schema trong `collectionSchemas` (projects, stories, testimonials, posts, products, branches): trường
    `data` theo schema đó.
  - Ref lỗi → `CrossTenantRefError`, không ghi gì.
  - Ghi + kiểm nên chạy được trong transaction của caller (repository dùng đúng `db` được truyền vào).
- `forPlatform(db)` — tra cứu nền tảng không theo tenant, chỉ có:
  - `domains.findByHostname(hostname)` → `findUnique({ where: { hostname } })` trên client nền tảng nội bộ
    (không qua guard thiếu tenant; vẫn qua guard connect). Seed chuyển sang dùng hàm này.
  - Client nền tảng: `createDb` dựng base client, trả bản có guard; giữ bản chỉ có guard connect trong `WeakMap` nội bộ
    `packages/db` để `forPlatform` lấy ra. Không export client không guard.

### 3. Rút ref từ zod (`packages/sections/src/refs.ts`)
```ts
export function collectRefs(schema: z.ZodType, value: unknown):
  { media: string[]; collections: Record<string, string[]> };
```
- Duyệt song song schema và giá trị: `object`, `array`, `optional`, `nullable`, `default`, `union`/`discriminatedUnion`
  (thử mọi nhánh khớp shape), `record`, `pipe`/`lazy` nếu có. Node có meta `fieldRegistry` `widget: "media"` → thêm
  `value.id`; `widget: "collectionQuery"` → thêm `value.ids` vào `collections[collection]`. Giá trị sai shape → bỏ qua
  (schema validate là việc khác).
- Export từ `@solar/sections`. `@solar/sections` chuyển từ devDependency sang dependency của `@solar/db` (workspace,
  không phải dependency mới bên ngoài). Tên `collection` trong `collectionQuery(...)` phải là `CollectionName` của db;
  tên lạ → `CrossTenantRefError` (fail đóng).

### 4. ESLint ranh giới Prisma
- `packages/config/eslint.config.mjs`: export `prismaBoundary` = `no-restricted-imports` cấm `@prisma/*`, `pg`,
  `**/generated/**` (và `@solar/db/generated*`) với thông báo "Dùng forTenant/forPlatform từ @solar/db". Gắn vào
  `nextConfig(...)` (áp cho `apps/*` và package dùng `nextConfig`); `packages/db/eslint.config.mjs` tắt luật này cho chính
  nó. Package nào dùng config khác (`packages/*` không gọi `nextConfig`) → thêm `prismaBoundary` vào config của package đó
  nếu package có `.ts`.
- Test lint: `packages/config` (hoặc `packages/db`) có test chạy `ESLint` API trên đoạn code mẫu
  `import { PrismaClient } from "@prisma/client"` với đường dẫn ảo `apps/web/src/app/x.ts` → 1 lỗi; cùng đoạn trong
  `packages/db/src/x.ts` → 0 lỗi.
