## Mục tiêu
Một bản `apps/web` phục vụ nhiều tên miền: `proxy.ts` đọc `Host`, tra bảng `Domain` qua cache 2 tầng, chặn tên miền lạ/đã
gỡ/tenant bị khóa, chuyển 308 về tên miền chính, rồi rewrite sang `/sites/<siteId>/…` với header nội bộ `x-tenant-id`,
`x-site-id` do proxy tự đặt. Header giả mạo từ client không có tác dụng.

### `apps/web/src/lib/tenant/host.ts` — chuẩn hóa
```ts
export function normalizeHost(raw: string | null): string | null
```
- Chữ thường, bỏ cổng, bỏ dấu `.` cuối, IDN → punycode (dùng `new URL("http://" + raw).hostname`); **không** bỏ `www.`.
  Rỗng, có `/`, `@`, khoảng trắng, IPv6/không hợp lệ → `null`.
- Chỉ đọc `request.headers.get("host")`. **Không** dùng `X-Forwarded-Host`, `Forwarded`, cũng không dùng
  `request.nextUrl.host` nếu Next tự lấy từ `x-forwarded-host` (kiểm bằng test). Lý do: proxy của Next không thấy IP
  socket để xác định "proxy tin cậy"; Caddy/ALB/Cloudflare đều đặt `Host` đúng → bỏ hẳn `X-Forwarded-Host` là cách hẹp
  nhất thỏa ranh giới tin cậy của story. Ghi vào README/ADR D7 một dòng.

### `apps/web/src/lib/tenant/resolver.ts` — cache 2 tầng
```ts
export type HostRecord = { hostname: string; tenantId: string; siteId: string; status: DomainStatus;
  isPrimary: boolean; tenantStatus: TenantStatus; primaryHost: string | null };
export type HostLookup = (hostname: string) => Promise<HostRecord | null>;
export type SharedStore = { get(key): Promise<string | null>; set(key, value, ttlSec): Promise<void>; del(keys): Promise<void> };
export type InvalidationBus = { publish(hostnames: string[]): Promise<void>; subscribe(cb: (hostnames: string[]) => void): void };
export function createHostResolver(opts: { lookup: HostLookup; store?: SharedStore; bus?: InvalidationBus;
  memoryTtlMs?: number /* 60_000 */; sharedTtlSec?: number /* 300 */; now?: () => number }): {
  resolve(hostname: string): Promise<HostRecord | null>;
  invalidate(hostnames: string[]): Promise<void>; // del store + publish + xóa bộ nhớ local
};
```
- Thứ tự: bộ nhớ (Map, TTL 60 s, cả kết quả `null` — cache âm, tránh dội DB bởi host lạ) → `store` (Redis, khóa
  `tenancy:host:<hostname>`, JSON, TTL 300 s; `null` lưu là `"null"`) → `lookup` (DB). Ghi ngược lên các tầng trên.
- Gộp request đồng thời cùng host (một promise đang chờ dùng chung). Giới hạn Map (vd. 10 000 mục, xóa mục cũ nhất).
- `invalidate`: xóa store, publish kênh `tenancy:host:invalidate`, xóa Map local. Mọi instance subscribe → xóa Map.
  Mất kết nối Redis rồi kết nối lại → xóa toàn bộ Map (không tin pub/sub đã nhận đủ). TTL 60 s là chặn trên khi lỡ.
- Lỗi store/bus (Redis chết) → bỏ qua tầng đó, đọc DB, log một lần; không làm site sập.
- `apps/web/src/lib/tenant/redis.ts`: `redisStore(url)`, `redisBus(url)` bằng `ioredis` (dependency mới của `apps/web`,
  đã chấp thuận — ghi lý do trong PR); hai kết nối (lệnh + subscriber). Không có `REDIS_URL` → không store, bus nội bộ
  (EventEmitter) cho một instance.
- `apps/web/src/lib/tenant/index.ts`: singleton `getHostResolver()` (giữ trên `globalThis` để HMR không tạo pool mới),
  `createDb({ pool: POOL_BUDGET.web })`, `lookup` = `forPlatform(db).domains.resolve`. `invalidateHosts(hostnames)`
  export để admin (E8) dùng; tới lúc đó chuyển sang package dùng chung nếu cần.

### `apps/web/src/proxy.ts`
Thứ tự xử lý, mỗi nhánh có test:
1. Luôn xóa `x-tenant-id`, `x-site-id` khỏi header request gửi tiếp (cả khi tắt `MULTI_TENANT`).
2. `pathname` là `/sites` hoặc bắt đầu `/sites/` → 404 (request từ ngoài; rewrite nội bộ không qua proxy lần nữa).
3. `host = normalizeHost(headers.host)`; `null` → 404.
4. `record = resolve(host)`; `null` hoặc `status` ∉ {`verified`, `active`} (gồm `removed`, `pending`, `error`) → 404.
5. `tenantStatus === "suspended"` → 403 (văn bản ngắn tiếng Việt, `Cache-Control: no-store`).
6. `!record.isPrimary && record.primaryHost && record.primaryHost !== host` → 308 tới
   `<proto>://<primaryHost><pathname><search>`; `proto` = `https` khi `NODE_ENV=production`, còn lại theo request.
7. Đặt `x-tenant-id`, `x-site-id`. `/api/*` → `NextResponse.next({ request: { headers } })` (route API đọc header;
   không rewrite). Còn lại → `NextResponse.rewrite(new URL("/sites/<siteId><pathname><search>", request.url), { request: { headers } })`.
- 404/403 trả `new NextResponse(text, { status })` — "404 trang nền tảng" dạng tối giản; trang 404 có thương hiệu nền
  tảng để sau.
- `config.matcher`: bỏ qua `_next/static`, `_next/image`, `fonts/`, `images/`, `videos/`, `preset-media/`, `backup/`,
  `favicon.*`, `logo.svg`, `site.webmanifest` (tài nguyên dùng chung). `robots.txt` **qua** proxy (theo tenant ở E5-S04).
- Route tạm `app/sites/[siteId]/[[...path]]/page.tsx`: gọi `notFound()` khi `x-site-id` (header) ≠ `params.siteId`,
  còn lại hiển thị khung tối giản "Site <siteId> · /<path>" (class token, nhãn tạm) — để kiểm rewrite end-to-end; E5-S04
  thay bằng renderer thật.

## Các bước
1. `forPlatform(db).domains.resolve` + kiểu export + int test (Postgres) — `packages/db/src/repository.ts`.
2. `host.ts` + test chuẩn hóa (hoa/thường, cổng, IDN `nănglượng.vn` → `xn--…`, dấu chấm cuối, `www.` giữ nguyên, rác → null).
3. `resolver.ts` + test với `lookup`/store/bus giả: trúng bộ nhớ không gọi lookup; hết TTL đọc lại; cache âm; gộp
   request đồng thời; `invalidate` ở instance 1 làm instance 2 (chung bus giả) đọc bản mới; Redis lỗi → vẫn trả từ DB;
   reconnect → xóa Map. Đo p95 trúng bộ nhớ (10 000 lần) ≤ 5 ms.
4. `redis.ts` + int test (skip khi thiếu `REDIS_URL`): 2 resolver, 2 kết nối Redis thật; đổi primary trong lookup giả +
   `invalidate` → resolver kia thấy bản mới ≤ 5 s.
5. `proxy.ts` + route tạm `sites/[siteId]/[[...path]]`; test proxy gọi hàm `proxy(new NextRequest(...))` với resolver
   giả (inject qua tham số/hàm tạo `createProxy(resolver)`; `proxy.ts` export bản dùng singleton):
   - 3 host → 3 tenant (header + đích rewrite đúng); host lạ → 404; `www.` không phải chính → 308 + `Location` đúng;
     `/sites/x` → 404; domain `removed` → 404; tenant `suspended` → 403; `/api/lead` → không rewrite, có header.
   - Giả mạo: request host A kèm `x-tenant-id: B`, `x-site-id: B`, `X-Forwarded-Host: <host B>`, `Forwarded: host=<B>`
     → header gửi tiếp là của A, đích rewrite của A.
   - `MULTI_TENANT` tắt: cho qua, header nội bộ đã bị xóa.
6. `apps/web/package.json` test script thêm file test mới; `tsconfig.test.json` thêm `paths` `@solar/db` nếu cần.
7. CI `workspace.yml` job `db`: thêm service `redis:7-alpine` + `REDIS_URL`, chạy test `apps/web` có Redis (hoặc test
   Redis của `web` trong job đó).
8. Kiểm thật: `pnpm db:seed`, `MULTI_TENANT=1 pnpm --filter web dev`, `curl -H "Host: t15.localhost" …`,
   `curl -H "Host: t12.localhost" …`, host lạ, `/sites/x`, kèm header giả mạo → ghi kết quả vào report.
   `pnpm --filter web build` một lần (Prisma trong proxy).
9. README `apps/web` (hoặc `packages/db/README.md`) mục "Phân giải tên miền"; tick AC.
