## Mục tiêu
`<PageRenderer page site />` (Server Component trong `@solar/sections`) render danh sách section `{id, type, variant,
enabled, anchor?, data}` theo đúng thứ tự qua registry, bỏ section tắt/không đủ quyền, và cô lập lỗi từng section ở cả
server (chuẩn bị dữ liệu) lẫn client (error boundary) — một section hỏng không làm sập trang (HTTP 200).

## Thiết kế

### Kiểu cấu hình trang — `packages/sections/src/page.ts`
```ts
export const pageSectionSchema = z.object({
  id: z.string().min(1),                       // sectionId, React key, dùng trong log
  type: z.string().min(1),
  variant: z.string().min(1),
  enabled: z.boolean().default(true),
  anchor: z.string().regex(/^[a-z0-9-]+$/).optional(),   // "du-toan" → id="du-toan"
  data: z.unknown(),                           // parse theo schema của type khi render
});
export const pageConfigSchema = z.object({ sections: z.array(pageSectionSchema) })
  .refine(unique id); // id trùng → lỗi
export type PageSection = z.output<typeof pageSectionSchema>;
export type PageConfig = z.output<typeof pageConfigSchema>;
```
`layout` của E5 để E5/E12 thêm (trường tùy chọn, không cần ở đây). Nơi đọc dữ liệu (E5) parse bằng `pageConfigSchema`;
renderer nhận `PageConfig` đã có kiểu.

### Renderer — `packages/sections/src/render/PageRenderer.tsx` (async Server Component)
```ts
type PageRendererProps = {
  page: PageConfig;
  site: SiteContext;
  registry?: SectionRegistry;                 // mặc định sectionRegistry; lab/test truyền registry demo
  canUse?: (feature: string) => boolean;      // E6 thay bằng (f) => can(site, f); mặc định cho phép
  loadData?: (input: { section: PageSection; data: unknown; site: SiteContext }) => Promise<unknown> | unknown;
};
```
`SectionRegistry = ReturnType<typeof createRegistry>` (export từ `registry.ts`).

Luồng:
1. Lọc `enabled !== false`; với `def.meta.entitlement` mà `canUse` trả false → bỏ **trước** khi gọi `load()` (không tải chunk).
   Type không có trong registry → bỏ (registry đã warn).
2. **Chuẩn bị song song** (`Promise.all`, mỗi phần tử tự `try/catch`, không bao giờ reject): `def.schema.parse(data)` →
   `loadData?.(…)` (E5: truy vấn collection; trả về data cho variant, mặc định giữ nguyên data đã parse) →
   `await resolved.load()`. Lỗi → `console.error("[sections] chuẩn bị section lỗi", { tenantId, sectionId, type, variant, error })`
   và section đó thành fallback rỗng. Song song → không thêm waterfall so với trang viết tay (Target TTFB).
3. Render theo thứ tự gốc; mỗi section:
   ```tsx
   <div id={anchor} data-section-id={id} data-section-type={type}>
     <SectionBoundary tenantId sectionId type>
       <Suspense fallback={null}><Variant data site sectionId /></Suspense>
     </SectionBoundary>
   </div>
   ```
   Fallback server = wrapper rỗng có thêm `data-section-fallback=""`. Wrapper giữ `id` neo nên link `#du-toan` không gãy khi
   section lỗi. Variant không tự gắn `id` neo (README).
   - `Suspense` mỗi section = kiểu `<Lazy>` của t13 (selective hydration) **và** điều kiện để lỗi render phía server của
     một section chỉ làm boundary đó render ở client thay vì hỏng shell (HTTP 200). Dữ liệu và module variant đã chuẩn bị
     xong ở bước 2 nên variant đồng bộ không suspend → HTML có đủ nội dung khi tắt JS. "Lazy-load dưới màn hình đầu" =
     island của variant tải qua chunk async (S01) + hydrate theo từng boundary; không mount bằng IntersectionObserver
     (mất nội dung khi tắt JS, hại SEO). Bọc cả section đầu (khác t13) để cô lập lỗi đồng nhất — ghi trong README.
   - **Cập nhật khi thực thi**: bỏ `Suspense`. Đo được: island `next/dynamic` (mẫu S01) luôn suspend khi SSR, nên
     section trong Suspense bị stream vào `<div hidden>` (`<template id="B:0">`) → không JS thì mất nội dung (vi phạm
     AGENTS.md). Chỉ giữ error boundary; lazy-load = chunk async của island. Lỗi render Server Component trên server
     không còn được cô lập — README yêu cầu đưa việc có thể lỗi vào `loadData`.
4. `SectionBoundary` (`render/SectionBoundary.tsx`, `"use client"`, class component): `getDerivedStateFromError` → render
   `null` (wrapper rỗng còn lại); `componentDidCatch` → `console.error("[sections] render section lỗi", { tenantId, sectionId,
   type, error })`. Không dùng `react-error-boundary` (không thêm dependency).
