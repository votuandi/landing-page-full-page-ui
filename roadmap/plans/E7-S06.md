## Mục tiêu
Tenant mở "Nội dung" trong CMS, thấy các collection nằm trong gói của mình (dự án, sản phẩm, danh mục sản phẩm, thương
hiệu, video Shorts, bài viết, FAQ, đánh giá, chi nhánh, chứng chỉ, báo chí, dịch vụ), và thêm/sửa/nhân bản/xóa/sắp xếp
bản ghi bằng form sinh từ **một schema dùng chung với web**. Lưu bản ghi đã xuất bản (hoặc đổi trạng thái) ghi Outbox
`tenant:<id>:collection:<name>` trong cùng giao dịch → worker revalidate → trang chủ + trang chi tiết cập nhật.
Collection ngoài gói bị ẩn ở menu và mọi action từ chối ở server.

**Tách story (Claude tự quyết theo ngưỡng L, 18/10/2026 — người dùng cho phép tự quyết trong phiên)**: nhập/xuất CSV
sản phẩm chuyển sang story mới **E7-S14** (thêm vào epic trong commit plan). Phần này giữ đủ 2 AC; giá/giá giảm,
nhiều ảnh, thông số, `provider` video vẫn ở đây (chỉ là trường của schema + một `refine`).

## Thiết kế

1. **Schema dùng chung** — `packages/db/src/collections.ts` (một file, export từ `@solar/db`; tách file nếu > ~300 dòng):
   ```ts
   type CollectionDef = {
     name: Collection;                      // tên model: "product" | "productCategory" | … (12, = COLLECTIONS)
     path: string;                          // đoạn URL admin: "san-pham", "du-an", "video", "bai-viet", "faq"…
     label: { vi: string; en?: string };
     entitlement?: Feature;                 // product/productCategory/brand → catalog; story → shorts; post → blog; pressItem → press
     columns: z.ZodObject;                  // cột riêng có thể sửa (price, salePrice, segment, kwp, rating, isPrimary, group, categoryId…)
     data: z.ZodType;                       // shape của cột `data` — đúng thứ web đang đọc
     defaults: { title: Localized; columns: …; data: … };
     filters?: readonly (keyof columns)[];  // lọc ở danh sách: segment, categoryId, group…
   };
   export const collectionDefs: Record<Collection, CollectionDef>;
   export const COLLECTIONS; // chuyển từ apps/web cacheTags.ts về đây, web import lại
   export function slugify(value: string): string; // bỏ dấu, đ→d, [a-z0-9-], ≤ 200; seed-data dùng lại
   ```
   - `data` của product/project/post/service lấy **đúng** `contentSchemas.ts` (chuyển schema sang file này; web import
     lại, không đổi hành vi). faq/certificate/pressItem: chuyển schema inline. branch/story/testimonial: viết schema của
     `data` sao cho loader hiện có map ra item hợp lệ của `collectionSchemas` (story dùng `storySource`).
   - Form phải render được bằng `SchemaForm` (trường ảnh hiện lưu chuỗi đường dẫn/uuid → giữ kiểu chuỗi, picker media
     là E8-S05). Product: `refine` `salePrice < price` (thông báo tiếng Việt) dùng `resolvePrice`.
   - `title` luôn localized `{ vi, en? }` (EN chỉ khi `bilingual`).

2. **Ghi dữ liệu** — `packages/db/src/collectionWrite.ts` (thuần repository, có `tenantId` bắt buộc):
   ```ts
   saveCollectionItem(db, tenantId, name, { id?, slug?, title, status, columns, data }): Promise<{ id: string; slug: string }>
   duplicateCollectionItem(db, tenantId, name, id): Promise<{ id: string }>   // slug "<slug>-ban-sao[-n]", status draft, order cuối
   deleteCollectionItem(db, tenantId, name, id): Promise<void>                // bị tham chiếu (FK Restrict) → CollectionError "Đang được dùng bởi …"
   reorderCollection(db, tenantId, name, ids: string[]): Promise<void>        // ids phải đúng tập hiện có, order = index
   class CollectionError extends Error { constructor(message: string, readonly status: 400 | 404 | 409) }
   ```
   - Validate bằng `collectionDefs[name]` trước khi ghi (lỗi → `CollectionError` 400 kèm message zod tiếng Việt).
   - `slug` trống → `slugify(title.vi)`; slug không hợp lệ → 400; trùng trong tenant → 409 "Đường dẫn đã được dùng"
     (kiểm trước + bắt P2002 khi đua).
   - `status: published` → `publishedAt = publishedAt ?? now`; `draft` → `publishedAt` giữ nguyên lịch sử hoặc null (chọn
     null, web chỉ lọc theo `status`).
   - **Invalidate**: trong cùng transaction, `enqueueInvalidate(repo, [collectionTag(tenantId, name)])` khi bản ghi
     **trước hoặc sau** là `published` (sửa nháp thuần không invalidate). Xóa/sắp xếp có bản ghi published → invalidate.
     Product thay đổi cũng invalidate `productCategory`/`brand`? Không — web gộp ở `products()` nên tag `product` đủ; đổi
     category/brand → invalidate tag của chính nó (web đọc cả ba khi dựng products).
   - FK (`categoryId`, `brandId`, `parentId`) phải thuộc cùng tenant (Prisma relation đã ràng `[tenantId, id]`; lỗi → 400).

3. **Admin** (`apps/admin`):
   - `src/lib/collections.ts` (deps tiêm vào, như `pageSections.ts`): `collectionTypes(can)` (lọc entitlement),
     `requireCollection(path, can)` → def hoặc null; `loadCollectionList(path, { q, status, filter }, deps)` (quyền
     `content.edit` trước; tìm theo slug + `title.vi` không dấu — lọc ở server, tối đa 500 bản ghi, sắp `order`),
     `loadCollectionItem(path, id)`; handlers `save`, `duplicate`, `remove`, `reorder` — mỗi handler kiểm collection
     trong gói **trước** khi gọi DB (ngoài gói → 403 "Gói hiện tại không có …").
   - `src/app/(admin)/noi-dung/actions.ts`: `action("content.edit", …)` cho 4 handler.
   - Trang: `/noi-dung` (lưới collection trong gói, có số bản ghi; giữ link nhỏ tới "Form section mẫu"),
     `/noi-dung/[collection]` (danh sách: ô tìm, lọc trạng thái + filter của def, bảng/thẻ có tiêu đề, slug, trạng thái,
     nút Sửa/Nhân bản/Xóa có xác nhận; kéo thả + nút ↑↓ chỉ bật khi không lọc/tìm), `/noi-dung/[collection]/moi`,
     `/noi-dung/[collection]/[id]` (form: tiêu đề, slug (tự sinh khi trống, gợi ý trực tiếp khi gõ tiêu đề), trạng thái,
     `SchemaForm` cho `columns` + `data`; Lưu → thông báo; lỗi 409 slug hiện tại trường slug).
     `path` không có trong gói → `notFound()`; route tĩnh `form` của E7-S03 giữ nguyên.
   - Nav: không cần mục con; `/noi-dung` chỉ hiện collection trong gói.

4. **Web**: `contentSchemas.ts`/`collections.ts`/`cacheTags.ts` import schema + `COLLECTIONS` từ `@solar/db` (một nguồn).
   Không đổi output của loader (test web hiện có phải xanh nguyên).
