# Plan E10-S01 — Image Docker cho `web`, `admin` và `console`

- Story: roadmap/epics/E10-deploy-ops.md · Cỡ: M
- Loại: logic (hạ tầng) · Người thực thi: codex · Reviewer: claude

## Mục tiêu
Một Dockerfile đa giai đoạn dùng chung (`ARG APP`) build image chạy được của `web` và `admin` từ monorepo pnpm/turbo,
chạy không root, `read_only`, có healthcheck `/api/health` (DB + Redis). CI build + smoke test mọi PR đụng Docker và
build + smoke + đẩy GHCR (tag = commit SHA) khi merge vào base; ECR khi đã cấu hình biến AWS.

## Bối cảnh đã khảo sát
- `Dockerfile`, `Dockerfile.dev`, `docker-compose.yml` ở gốc: bản cũ (npm/yarn, `npx prisma generate`, `/app/prisma`)
  — không ai tham chiếu ngoài nhau (`git grep Dockerfile docker-compose.yml`). `.dockerignore` chỉ bỏ `node_modules` gốc.
- `apps/console` **chưa tồn tại** (E15-S02). Story này làm Dockerfile tổng quát theo `APP`; console chỉ cần thêm một dòng
  vào matrix của workflow khi E15-S02 tạo app → ghi vào epic E15-S02 (Chi tiết) một câu nhắc.
- Next 16.3.8, `next build --webpack`; `apps/web/next.config.ts`, `apps/admin/next.config.ts` chưa có `output`.
  `next start` với `output: "standalone"` chỉ in cảnh báo (`next/dist/server/next.js:243`) → e2e production vẫn chạy.
- Prisma 7 generator `prisma-client` → `packages/db/generated` (TS, transpile qua `transpilePackages`), adapter-pg, không
  engine nhị phân. `@solar/db#build` = `prisma generate`; `prisma.config.ts` không cần DB để generate.
- DB: `createDb` / `checkConnection` (`packages/db/src/client.ts:52,90`) — `checkConnection` kiểm role `app_runtime`
  cô lập, **chưa export** từ `packages/db/src/index.ts`. Web: `getWebDb()` (`apps/web/src/lib/tenant/db.ts`).
  Admin: `getRuntime()` (`apps/admin/src/lib/runtime.ts`) tạo `db` + `redis` nhưng không trả `redis`.
- Redis: web có client riêng trong `getRateLimiter()` (`apps/web/src/lib/tenant/rateLimit.ts:43`) và `createRedisCache`.
- Proxy: `apps/web/src/proxy.ts` (matcher) rewrite theo host khi `MULTI_TENANT=1`; `apps/admin/src/proxy.ts` rewrite
  host lạ → `/loi/khong-tim-thay` 404. Healthcheck gọi `127.0.0.1` → **phải loại `api/health` khỏi matcher** cả hai.
- Ghi đĩa lúc chạy: `.next/cache` (ảnh `next/image`, sharp có trong `apps/web`), ISR flush xuống `.next/server`
  (`experimental.isrFlushToDisk`, mặc định true) — với `read_only` sẽ EROFS → tắt flush (cache bộ nhớ; Redis ở E10-S03).
- CI: `.github/workflows/workspace.yml`, action `.github/actions/db-setup` (Postgres 16 + role + migrate + seed).
- Truy vấn: `codegraph explore "createRedisCache getRuntime"`, `"checkConnection createDb POOL_BUDGET storageFromEnv"`.

## Thiết kế
- **Dockerfile** (gốc, thay bản cũ), `ARG APP`:
  1. `base`: `node:22-alpine` (pin tag cụ thể, vd. `node:22.x-alpine3.2x`), `corepack enable` (pnpm theo `packageManager`).
  2. `prune`: `COPY . .` → `pnpm dlx turbo@2.11.7 prune $APP --docker`.
  3. `build`: `COPY out/json` + lockfile → `pnpm install --frozen-lockfile` (cache mount pnpm store) → `COPY out/full`
     → `pnpm turbo run build --filter=$APP` với `ENV MULTI_TENANT=1 NEXT_TELEMETRY_DISABLED=1`. Build **không cần DB**.
  4. `runner`: `node:22-alpine`, `NODE_ENV=production`, user `nextjs` (1001), copy `apps/$APP/.next/standalone` →
     `/app`, `.next/static` → `/app/apps/$APP/.next/static`, `apps/$APP/public` (nếu có) → `/app/apps/$APP/public`.
     `WORKDIR /app/apps/$APP`, `ENV PORT=3000 HOSTNAME=0.0.0.0`, `HEALTHCHECK` wget, `CMD ["node","server.js"]`.
     Không copy `node_modules` ngoài standalone, không giữ `pnpm`/`turbo` trong runner.
- **next.config** (cả hai): `output: "standalone"`; web thêm `experimental.isrFlushToDisk: false` (lý do: read-only,
  cache dùng chung ở E10-S03). Không cần `outputFileTracingRoot` (Next tự lấy gốc theo `pnpm-lock.yaml`) — nếu standalone
  thiếu package workspace thì đặt `outputFileTracingRoot` về gốc repo.
- **`/api/health`** mỗi app: `src/app/api/health/route.ts` gọi `healthResponse(checks)` trong `src/lib/health.ts` của app
  (≈15 dòng; chạy các check song song, mỗi check timeout 2 s, trả `Response.json` 200/503 + `no-store`; lỗi chỉ log
  tên check, không log/không trả message). Web: `db` = `checkConnection(getWebDb())` khi có `DATABASE_URL`, `redis` =
  `ping` client Redis đang có (đưa client ra từ `rateLimit.ts`, không tạo kết nối mới mỗi request). Admin: `getRuntime()`
  trả thêm `redis`; `db` = `checkConnection(runtime.db)`. Route `dynamic` (web `cacheComponents`: dùng `await connection()`).
- **Proxy**: thêm `api/health` vào phần loại trừ của `matcher` cả web và admin.
- **`.dockerignore`**: `**/node_modules`, `**/.next`, `**/.turbo`, `.git`, `.agent-runs`, `.codegraph`, `graphify-out`,
  `tooling/visual/test-results`, `**/.test-dist`, `packages/db/generated`, `.env*` (giữ `.env.example`), `*.pem`.
- **`infra/docker/smoke.sh <app> <image>`**: bash, đọc `DATABASE_URL`, `REDIS_URL`, (admin: `ADMIN_SESSION_SECRET`,
  `PLATFORM_DOMAIN`), `SMOKE_NETWORK` (mặc định `host` cho CI; local Windows dùng bridge + `-p`, URL `host.docker.internal`).
  Kiểm theo R3, R5, R11, R12, R13 + biến thể DB sai → health 503 trong ≤ 5 s. In bảng kết quả, exit ≠ 0 khi FAIL; dọn container.
- **`.github/workflows/images.yml`**: `pull_request` (paths: `Dockerfile`, `.dockerignore`, `infra/docker/**`, workflow,
  `apps/*/next.config.ts`, `apps/*/src/app/api/health/**`, `apps/*/src/lib/health.ts`, `pnpm-lock.yaml`) + `push` base +
  `workflow_dispatch`. Matrix `app: [web, admin]`. Services postgres/redis như job `db`, `db-setup` → `docker buildx build
  --load` (cache `type=gha`) → smoke → (chỉ push/dispatch trên base) login GHCR (`GITHUB_TOKEN`, `packages: write`) và
  push `ghcr.io/${owner,,}/${repo}-<app>:<sha>`; ECR khi `vars.AWS_ECR_REGISTRY != ''` qua
  `aws-actions/configure-aws-credentials` (OIDC, `id-token: write`) + `aws-actions/amazon-ecr-login`.
- `infra/docker/README.md`: lệnh build/run, biến bắt buộc, `read_only` + tmpfs/volume (`STORAGE_LOCAL_ROOT` khi driver local).
