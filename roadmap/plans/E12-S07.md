## Mục tiêu
Tenant có `landingPages` tạo landing ở admin (trang trắng / mẫu trang / nhân bản), đặt SEO riêng và ẩn header/footer;
landing đã xuất bản phục vụ ở `/<slug>`, có trong sitemap; vượt `limits.pages` bị chặn ở server.

## Bối cảnh đã khảo sát
- Đã có: render `/<slug>` cho `Page` ngoài danh mục (`apps/web/src/components/tenant/cached.tsx:24-38`), sitemap lọc landing
  theo `landingPages` (`apps/web/src/lib/tenant/seoData.ts:15`), `validateSiteStructure` đếm home+landing theo `pagesLimit`
  và chặn landing ngoài gói (`packages/presets/src/structure.ts:88,107-110`), `isLandingSlug`.
- Mẫu ghi có khóa + validate: `setPageTypes` (`packages/db/src/siteStructure.ts`); handler có deps: `apps/admin/src/lib/pageTypes.ts`.
- Publish lần đầu (`publishedAt` null) đã invalidate `siteTag` → sitemap (`packages/db/src/publish.ts:125`).
- Header/footer do `TenantChrome` ở layout render; mỗi section bọc `data-section-type` (`packages/sections/src/render/PageRenderer.tsx:71`).
- `tenantBackupSchema.pages` là `strictObject` (`packages/db/src/tenantBackup.ts:41`); `slugify` ở `packages/db/src/collections.ts:65`.
- Truy vấn: `codegraph explore "page kind landing slug sitemap limits.pages"`, `codegraph impact createPageSectionHandlers`, checks-map.

## Thiết kế
- **Dữ liệu**: cột `Page.settings Json?` (migration `20261105120000_e12_s07_page_settings`). Schema `pageSettingsSchema`
  ở `packages/presets/src/pageSettings.ts`: `{ seo?: { title?: {vi,en?}, description?: {vi,en?}, noindex?: boolean }, hideHeader?: boolean, hideFooter?: boolean }`
  (`strictObject`, title ≤ 70, description ≤ 160). Một cột Json thay vì 3 cột → backup/zod một chỗ.
  Đọc: `parsePageSettings(value)` = `safeParse` lỗi → `{}` + `console.error` → bản ghi cũ/hỏng không làm sập trang.
- **Slug**: `landingSlugIssue(slug): string | null` ở `packages/presets/src/pageSettings.ts`: 1–3 đoạn `^[a-z0-9]+(?:-[a-z0-9]+)*$`,
  ≤ 120 ký tự; cấm slug danh mục (`isLandingSlug` false), đoạn đầu trùng tiền tố collection/policy (`PAGE_TYPES[*].slug`
  kind collection/policy) hoặc `sites|api|lab`. Test chéo ở `apps/web` (`routes.test.ts`): mọi slug hợp lệ → `resolveRoute`
  trả `kind:"page"` → không tạo được landing mà web không phục vụ.
- **Mẫu trang**: `packages/presets/src/pageTemplates.ts` `PAGE_TEMPLATES: Record<id,{label:{vi}, title:{vi}, slug, sections: readonly string[]}>`
  — `ho-gia-dinh`: hero, process, calculator, testimonials, faq, lead-form · `nha-xuong`: hero, stats, process, trust, faq, lead-form
  · `tuyen-dai-ly`: hero, dealer, process, faq, cta-banner. Variant = variant của type trong home preset nếu có, không thì `t15`
  → mẫu khớp nhận diện site. Nội dung = `defaults` của type (đã gắn `[DỮ LIỆU MẪU]`).
- **db** `packages/db/src/landingPages.ts` (export từ `@solar/db`):
  - `createLandingPage(db, tenantId, { siteId, title, slug, source: {kind:"blank"} | {kind:"template", id} | {kind:"duplicate", pageId} })`
    → `{ pageId }`. Thứ tự trong một `withTenantTransaction`: đọc site+tenant → **khóa hàng Site** (`repo.site.update(id, { pageTypes: site.pageTypes })`)
    → đọc lại danh sách Page → validate (slug, trùng slug → `SiteSettingsError 409 "Đường dẫn đã được dùng"`, nguồn không có → 404)
    → `validateSiteStructure(proposed + {slug, sections: []})` → tạo Page (`sections: []`, `draftSections`, `publishedAt: null`)
    + SectionContent (`data: defaults`, `draftData`). Khóa trước khi đếm → hai request song song không cùng lọt limit.
  - Section ngoài gói (`sectionRegistry.getType(t).meta.entitlement`) bị bỏ khi dựng từ mẫu/nhân bản; nhân bản bỏ
    `site-header`/`site-footer` (chrome của home), giữ id section nguồn, copy `draftData ?? data` + `schemaVersion`,
    bỏ hàng `removedAt != null`. Trang mới chưa xuất bản → không invalidate.
  - `savePageSettings(db, tenantId, { pageId, title: {vi,en?}, settings })`: chỉ trang `isLandingSlug && slug !== ""`;
    không dùng revision lock của section (cài đặt tách khỏi bố cục → builder đang mở không bị 409); áp dụng ngay;
    trang đã xuất bản → `enqueueInvalidate([pageTag(tenantId, slug), siteTag(tenantId)])` (siteTag cho sitemap/noindex).
- **Admin** (`apps/admin/src/lib/landingPages.ts`: handler có deps như `pageTypes.ts`; actions trong `trang/actions.ts`):
  - `createLanding` = `action("pages.structure", …)`; thành công → `redirect("/trang/<id>")`. `saveLandingSettings` = `action("pages.structure", …)`.
  - `/trang`: khối "Landing page" — `Đã dùng {n}/{limit} trang` (n = home + landing), link "Tạo landing page" → `/trang/moi`;
    thiếu quyền/gói/đã đủ → lý do + "Nâng cấp gói" (`UpgradeRequest feature="landingPages"`).
  - `/trang/moi`: form chạy không cần JS; JS chỉ gợi ý slug từ tên (dùng `slugify`) khi người dùng chưa sửa slug.
  - `/trang/[pageId]`: trang landing có form "Cài đặt trang" (hiện ô EN khi site có `en`).
- **Web**: `loadPage` trả thêm `settings`; `tenantPage` dùng `seo.title || title`, `seo.description`, trả `noindex`;
  `tenantMetadata(..., { noindex })` → `robots: { index: false, follow: true }`; sitemap bỏ trang `noindex`
  (`listPublishedPages` trả `settings`). Ẩn header/footer: `tenantPage` chèn `<style>` `[data-section-type=site-header]{display:none}`
  (và footer) vào nội dung trang → layout không cần biết slug, chạy khi tắt JS, không đổi DOM chrome.
- **checks-map**: thêm `packages/presets/src/pageTemplates.ts`, `pageSettings.ts` vào `except` của matrix/visual/thumbnails
  (không đổi pixel trang có sẵn) + test trong `checks-map.test.mjs`. `pages.ts` vẫn kéo matrix → đặt `landingSlugIssue` trong `pageSettings.ts`.
