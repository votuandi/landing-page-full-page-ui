## Mục tiêu
Package `@solar/auth` dùng chung cho `apps/admin` (realm `site`, E7-S01) và `apps/console` (realm `platform`, E15-S02):
phiên lưu DB, mật khẩu scrypt, TOTP + mã dự phòng, rate-limit/khóa đăng nhập, `parseLoginId`, danh mục permission.
Hai realm không thể dùng phiên/tài khoản của nhau. Không thêm dependency runtime.

## Thiết kế
Package mới `packages/auth` (`@solar/auth`, `type: module`, exports `"."` → `src/index.ts`, `"./db"` → `src/db.ts`).
`src/index.ts` thuần (không import Prisma) để test đơn vị nhanh; `src/db.ts` chứa adapter DB phụ thuộc `@solar/db`.
Dependency: `@solar/core`, `@solar/db` (workspace). Không thêm package ngoài.

1. `password.ts`
   - `hashPassword(pw)` / `verifyPassword(pw, stored)` → `scrypt` async (`node:crypto` `scrypt` promisified), định dạng
     như seed, so sánh `timingSafeEqual`. Hash không hợp lệ → `false` (không ném). Có `dummyVerify()` chạy một lần
     scrypt giả khi không tìm thấy tài khoản để thời gian phản hồi như nhau.
   - `checkPasswordPolicy(pw, { identifiers })` → `{ ok } | { ok: false, reason }`: ≥ 10 ký tự, ≤ 128, không nằm trong
     `COMMON_PASSWORDS` (so chữ thường), không trùng định danh. Thông báo lỗi tiếng Việt.
   - `commonPasswords.ts`: 1.000 mật khẩu phổ biến nhất (lấy từ SecLists
     `Passwords/Common-Credentials/10k-most-common.txt`, MIT — ghi nguồn + license ở đầu file) cộng ~20 mật khẩu phổ
     biến tiếng Việt (`matkhau123`, `123456789a`…). Lưu dạng mảng string, export `Set`.
2. `totp.ts` — RFC 6238/4226 tự viết: `base32Encode/Decode`, `generateTotpSecret()` (20 byte), `totp(secret, time,
   { step: 30, digits: 6, algorithm: "sha1" })`, `verifyTotp(secret, code, now, window = 1)` (±1 bước, so sánh hằng
   thời gian), `otpauthUri({ issuer, account, secret })`. Mã dự phòng: `generateBackupCodes(n = 10)` → mã hiện cho
   người dùng (8 ký tự base32, dạng `xxxx-xxxx`) + hash `sha256` để lưu; `consumeBackupCode(hashes, code)` → mảng hash
   còn lại hoặc `null`.
3. `loginId.ts` — `parseLoginId(input)` → `{ kind: "email", value } | { kind: "phone", value } | { kind: "username",
   value }`, sai → ném `InvalidLoginIdError`:
   - trim; có `@` → email chữ thường, kiểm dạng `local@domain.tld` đơn giản;
   - chỉ gồm chữ số/`+`/khoảng trắng/`.`/`-` → `normalizeVnPhone`, phải qua `isVnMobile`;
   - chữ thường hóa; khớp `^[a-z0-9_]{3,40}$` và có ít nhất một chữ cái → username;
   - còn lại → lỗi. (`NangLuongSolar_Admin` → `nangluongsolar_admin`.)
4. `permissions.ts`
   - `PERMISSIONS` (const tuple) nhóm theo khu vực CMS: `dashboard.view`; `pages.view`, `pages.edit`, `pages.publish`,
     `pages.structure`; `content.edit`; `media.view`, `media.manage`; `leads.view`, `leads.manage`; `theme.manage`;
     `domains.manage`; `email.manage`; `billing.view`; `users.view`, `users.manage`; `settings.manage`; `audit.view`;
     `clients.view`, `clients.manage`, `bookings.view`, `bookings.manage`; nhóm `account.security` =
     `account.password`, `account.totp`, `users.resetPassword`, `users.transferOwner`, `users.delete`;
     `storefront.account`, `storefront.cart`, `storefront.booking`.
   - `PERMISSION_GROUPS` (`{ "account.security": [...] }`) + nhãn tiếng Việt `PERMISSION_LABELS` (console E15-S05 dùng).
   - `ROLE_PERMISSIONS`: owner = mọi quyền không phải `storefront.*`; admin = owner trừ `users.transferOwner`; editor = `dashboard.view`, `pages.*`, `content.edit`,
     `media.*`, `account.password`, `account.totp`; staff = `dashboard.view`, `leads.*`, `clients.view`, `bookings.*`,
     `media.view`, `account.password`, `account.totp`; viewer = `dashboard.view`, `pages.view`, `media.view`,
     `account.password`, `account.totp`; client = `[]` ở audience admin.
   - `effectivePermissions({ role, kind, audience, policy })` → `ReadonlySet<Permission>`:
     audience `storefront` → chỉ `storefront.*` (mọi role đang hoạt động); audience `admin` + role `client` → rỗng;
     `kind: "ghost"` → quyền của owner trừ nhóm `account.security`; sau cùng trừ `policy.deny` (zod parse
     `{ deny?: string[] }`, chấp nhận tên quyền hoặc tên nhóm; giá trị lạ bỏ qua). Không có đường nào thêm quyền.
   - `hasPermission(set, perm)`, `class ForbiddenError`.
5. `rateLimit.ts` — `Counter` (như web), `memoryCounter()`, `redisCounter(client: { eval(...) })` (kiểu cấu trúc, không
   import `ioredis`), `createLoginLimiter({ primary?, fallback?, maxFailures = 5, lockMs = 15 phút, ipLimit = 30,
   ipWindowMs = 15 phút })`:
   - `check({ realm, tenantId, identifier, ip })` → `{ ok } | { ok: false, retryAfterSec }` (đọc, không tăng);
   - `fail(...)` tăng khóa `auth:fail:<realm>:<tenantId|-> :<identifier>` và `auth:ip:<realm>:<ip>`;
   - `succeed(...)` xóa bộ đếm định danh. Khóa theo `(realm, tenantId, identifier)` → tenant A không khóa tenant B.
   - Redis lỗi → fallback bộ nhớ (như web). Không tự tạo kết nối.
6. `realm.ts` — `createRealm({ name, cookieName?, secret, sessionTtl, idleTtl, store, limiter, now? })`:
   - Cookie mặc định `__Host-<name>_sid` (production) / `<name>_sid` (khi `secure: false`, dùng cho `http://*.localhost`
     ở dev/e2e — WebKit/Firefox không nhận cookie `Secure` trên http). `cookieOptions()` → `{ name, httpOnly: true,
     secure, sameSite: "lax", path: "/", maxAge }`, không có `domain`.
   - Giá trị cookie = `<token>.<mac>`; `token` = 32 byte ngẫu nhiên base64url; `mac = HMAC-SHA256(secret,
     "<realm>:" + token)` base64url. DB lưu `sha256(token)` hex. Cookie sai `mac` (vd. phiên realm khác, secret khác)
     → `null` trước khi chạm DB.
   - `login({ identifier, password, totp?, tenantId?, ip, userAgent })`: `parseLoginId` (realm platform chỉ nhận email)
     → limiter.check → `store.findAccount` → `verifyPassword` (không thấy → `dummyVerify`) → kiểm `status === "active"`,
     audience/role (store quyết định, vd. site-admin loại `client`), `tempPasswordExpiresAt` quá hạn → lỗi
     `temp_password_expired` (thông báo hướng dẫn liên hệ hỗ trợ), TOTP nếu tài khoản bật (thiếu mã →
     `{ ok: false, reason: "totp_required" }`; mã sai → tính là một lần sai). Mọi lỗi khác → một thông báo chung
     `"Thông tin đăng nhập không đúng"`; bị khóa → `"Tạm khóa đăng nhập, thử lại sau N phút"` (không phân biệt tài khoản
     có tồn tại). Thành công → `store.createSession`, trả `{ ok: true, cookie, session }`.
   - `getSession(cookieValue, { tenantOfHost? })`: realm `site` **bắt buộc** `tenantOfHost`, `session.tenantId !==
     tenantOfHost` → `null`. Hết `expiresAt` hoặc quá `idleTtl` từ `lastSeenAt` → xóa phiên, `null`. Cập nhật
     `lastSeenAt` tối đa 1 lần/phút. Trả `{ id, realm, tenantId?, accountId?, kind, audience?, role?,
     mustChangePassword, permissions, expiresAt }` (permissions từ `effectivePermissions`; realm platform: rỗng ở
     story này).
   - `requireSession(cookie, { tenantOfHost?, allowMustChange? })` → ném `UnauthenticatedError` (401) hoặc
     `MustChangePasswordError` khi `mustChangePassword && !allowMustChange`.
   - `logout(cookie)` xóa phiên; `rotate(cookie)` tạo token mới, xóa token cũ (gọi sau đổi mật khẩu / bật 2FA);
     `revokeAll(accountId, { except? })`.
   - `changePassword(session, { current, next })`: kiểm current (trừ khi `mustChangePassword`), policy, lưu hash, xóa
     `mustChangePassword`/`tempPasswordExpiresAt`, `revokeAll` trừ phiên hiện tại, `rotate`.
   - TOTP: `beginTotp(session)` → secret + uri (chưa lưu); `enableTotp(session, secret, code)` → lưu secret + hash mã dự
     phòng, trả mã dự phòng một lần; `disableTotp(session, code)`.
   - Phiên `kind: "ghost"` chỉ đọc được (tạo ở E15-S07); `getSession` coi grant bị thu hồi/hết hạn là `null`.
7. `SessionStore` (interface trong `realm.ts`) + `memoryStore()` cho unit test. Adapter DB trong `src/db.ts`:
   - `siteStore(db: Db, { audience })`: mọi truy vấn qua `withTenantTransaction(db, tenantId, …)`; `findAccount` tìm
     `SiteUser` theo đúng một trong `email|phone|username` **trong tenant đó**; audience `admin` từ chối role `client`;
     phiên tạo với `audience` cố định; `findSession(tokenHash, tenantId)` chỉ tìm trong tenant của host (RLS) và đúng
     `audience`; ghost: join `GhostGrant` kiểm `revokedAt IS NULL`.
   - `platformStore(db: PlatformDb)`: `PlatformAdmin`/`PlatformSession` qua `forPlatform`.
   - `SiteUser`/`PlatformAdmin` chưa có chỗ lưu mã dự phòng → migration `20261019000000_auth_backup_codes`: thêm
     `totpBackupCodes String[] @default([])` cho cả hai bảng; cập nhật `ERD.md` (`pnpm --filter @solar/db db:erd`).
8. README `packages/auth/README.md`: API, cookie, quy tắc realm, cách app cấu hình (`ADMIN_SESSION_SECRET`,
   `CONSOLE_SESSION_SECRET` ≥ 32 byte; thiếu → ném lỗi khi gọi, không ở module scope).

## Rủi ro / câu hỏi mở
- [không chặn] `__Host-` cần `Secure`; dev/e2e chạy http → tùy chọn `secure: false` đổi tên cookie bỏ tiền tố. Production
  luôn `secure: true` (app truyền `process.env.NODE_ENV === "production"`).
- [không chặn] Story ghi "secret" cho realm nhưng cookie chỉ chứa token ngẫu nhiên → dùng secret làm MAC gắn realm vào
  cookie (từ chối sớm phiên realm khác), DB vẫn lưu `sha256(token)`.
- [không chặn] Cột `failedLogins`/`lockedUntil` đã có nhưng khóa dùng bộ đếm Redis/bộ nhớ theo story (khóa theo tenant +
  định danh cả khi tài khoản không tồn tại → không lộ tồn tại). Không ghi hai cột này.
