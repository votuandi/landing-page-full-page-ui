## Mục tiêu
Dữ liệu section lưu với `schemaVersion` cũ (cột `SectionContent.data`/`draftData`, nội dung trong `PageVersion.snapshot`,
file backup JSON) luôn được nâng lên version hiện tại trước khi parse; khi lưu thì ghi lại bản đã nâng. Có script
`pnpm sections:migrate [--dry-run]` chạy toàn DB, và test làm CI fail khi tăng `schemaVersion` mà thiếu migration.

## Thiết kế
1. **Khung thuần JSON** — `packages/sections/src/migrate.ts`:
   ```ts
   export type SectionMigration = (data: Record<string, unknown>) => Record<string, unknown>;
   // SectionTypeDef thêm: migrations?: Record<number, SectionMigration>  // khóa n = bước n → n+1
   export function migrateSectionData(def: SectionTypeDef, fromVersion: number, data: unknown):
     { schemaVersion: number; data: unknown; changed: boolean };
   export function missingMigrations(def: SectionTypeDef): number[]; // các n trong [1, schemaVersion) thiếu migrations[n]
   ```
   - `fromVersion === def.schemaVersion` → trả nguyên (`changed: false`) — idempotent.
   - `fromVersion < def.schemaVersion` → chạy lần lượt `migrations[fromVersion] … migrations[schemaVersion-1]`; thiếu bước
     → throw `Error` nêu type + bước. `data` không phải object → throw.
   - `fromVersion > def.schemaVersion` (app cũ gặp dữ liệu mới trong rolling deploy) → trả nguyên, `changed: false`,
     `console.warn` một lần; schema hiện tại tự bỏ key lạ khi parse.
   - Export từ `index.ts`: `migrateSectionData`, `missingMigrations`, `migrateSnapshot` (dưới), kiểu `SectionMigration`.
2. **Nối migration có sẵn vào def**: mỗi type có `migrations.ts` thêm `migrations: { 1: migrateXV1, 2: … }` vào
   `defineSectionType(...)`. Không đổi nội dung các hàm migration, không tăng `schemaVersion` nào.
3. **Snapshot** — `migrateSnapshot(snapshot, registry = sectionRegistry)` trong `migrate.ts`: với mỗi phần tử
   `contents[]` có `type` đã đăng ký → migrate `data`, cập nhật `schemaVersion`; type lạ giữ nguyên. Trả
   `{ snapshot, changed }`. Dùng chung cho `PageVersion.snapshot` và file backup.
4. **Lazy đọc / ghi lại khi lưu** — `packages/db/src/sectionContent.ts`:
   - `migrateSectionRow(row)` → `{ ...row, schemaVersion, data, draftData, changed }` migrate cả `data` và `draftData`
     (draftData null giữ null) từ `row.schemaVersion`. Hàm đọc E5-S04/E7 sẽ gọi.
   - `forTenant().sectionContent.update`: khi input có `data` hoặc `draftData` → migrate bản ghi cũ (đã đọc sẵn, thêm
     `schemaVersion` vào `select`) lên version hiện tại, ghép input (coi là version hiện tại), ghi `schemaVersion` hiện
     tại. Nhờ đó trường không gửi lên (vd. `data` khi chỉ lưu nháp) cũng được nâng, hai trường luôn cùng version.
   - `create`: thiếu `schemaVersion` → điền version hiện tại của type.
5. **Script toàn DB** — `packages/db/scripts/sections-migrate.ts` (tsx), script `sections:migrate` trong
   `packages/db/package.json` và root `package.json` (`pnpm --filter @solar/db sections:migrate`):
   - Đọc danh sách tenant, mỗi tenant dùng `forTenant(db, id)` để duyệt `sectionContent` (theo lô, `orderBy id`) và
     `pageVersion`; áp `migrateSectionRow` / `migrateSnapshot`; chỉ ghi bản ghi `changed`.
   - `--dry-run`: không ghi, in tóm tắt `tenant · bảng · type vX→vY · số bản ghi`; exit 0. Lỗi migration (thiếu bước,
     data hỏng) → in id bản ghi, tiếp tục, exit 1 cuối cùng.
   - `--file <path>`: migrate một file backup JSON có dạng snapshot (hoặc mảng snapshot); dry-run chỉ in, không thì ghi
     đè file (ghi file tạm rồi rename). Định dạng backup E7 phải dùng lại dạng snapshot (ghi trong README).
   - Chạy lần hai sau khi migrate → 0 thay đổi (idempotent).
6. **CI chặn thiếu migration** — test `packages/sections/src/__tests__/migrations.test.ts` duyệt mọi def trong
   `sectionRegistry` + `widgetRegistry` (và test web cho demo lab nếu demo có `schemaVersion > 1`): `missingMigrations(def)`
   phải rỗng. Test chạy trong `pnpm turbo run test` của job `verify` → tăng version mà thiếu migration là CI đỏ.
7. **Expand/contract** — cùng file test: với mỗi def có migrations, chạy từng bước trên `defaults` và trên dữ liệu v1
   tối thiểu khi có; khẳng định mọi key đầu vào còn nguyên giá trị (`deepEqual`) ở đầu ra (migration chỉ thêm trường) và
   kết quả cuối parse được bằng `def.schema`. Thêm một test type demo v1/v2 trong test: dữ liệu v2 đã migrate parse được
   bằng schema v1 (mô phỏng app bản cũ) và không có schema nào dùng `.strict()` ở cấp object section.

## Các bước

   — kiểm bằng: typecheck.
2. Nối migrations vào 10 def có sẵn — file: `<type>/schema.ts` (calculator, cta-banner, hero, projects, segments,
   shorts, site-header, social, trust, widgets/quote-cart) — kiểm bằng: test bước 3.
3. Test khung + CI-guard + expand/contract + snapshot — file: `packages/sections/src/__tests__/migrations.test.ts`, thêm
   vào script `test` của `packages/sections/package.json` — kiểm bằng: `pnpm --filter @solar/sections test`.
   Test bắt buộc: v1→v2 đúng; v1→v3 (shorts) qua 2 bước; idempotent (migrate lần 2 = lần 1, `changed:false`); thiếu bước
   → throw; version cao hơn → nguyên dạng; snapshot có type lạ; `missingMigrations` trên def giả thiếu bước trả `[n]`.
4. `migrateSectionRow` + hook `create`/`update` của repository — file: `packages/db/src/{sectionContent,repository,index}.ts`
   — unit test `packages/db/src/__tests__/sectionContent.test.ts` (data + draftData + null draftData) và mở rộng
   `repository.int.test.ts`: update bản ghi v1 chỉ với `draftData` → `data` cũng được nâng, `schemaVersion` hiện tại.
5. Script `sections:migrate` — file: `packages/db/scripts/sections-migrate.ts`, `packages/db/package.json`,
   `package.json` — int test `packages/db/src/__tests__/sectionsMigrate.int.test.ts`: chèn SectionContent `shorts` v1
   (data + draftData) và PageVersion có snapshot v1 → `--dry-run` không đổi DB và báo 2 bản ghi; chạy thật → v3 ở cả
   hai bảng; chạy lại → 0 thay đổi. Unit test cho `--file` dùng file tạm.
   Logic script tách thành hàm export (`runSectionsMigrate({ db, dryRun, file })`) để test gọi trực tiếp; file CLI chỉ
   parse argv.
6. README: `packages/sections/README.md` (mục migration: cách thêm bước, quy tắc expand/contract, CI-guard) và
   `packages/db/README.md` nếu có (lệnh `sections:migrate`). Tick AC trong `roadmap/epics/E03-sections.md`.
