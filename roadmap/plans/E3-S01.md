## Mục tiêu
Tạo package `@solar/sections` với API khai báo section thống nhất (`defineSectionType`, `defineVariants`), registry
tra variant có fallback, và kiểu `SectionProps` sinh từ zod schema — để S02–S09, CMS và renderer dùng chung. Chứng minh
bằng trang lab rằng variant là Server Component, island tương tác tách bằng `next/dynamic`, JS của variant không dùng
không tải về trình duyệt.

  `packages/core` / `packages/tokens` (test `node:test`: `tsconfig.test.json` biên dịch CommonJS ra `.test-dist`).
- `zod` 4.6.5 đã có trong `packages/tokens` (D5, D12 cho phép) — dùng đúng phiên bản này.

  production trừ khi `LAB_ENABLED=true`; trang mẫu `lab/ui`, `lab/themes`.
- Playwright: `tooling/visual` (`playwright.config.ts` chạy `pnpm --filter web start --port 3210`, config phụ
  `playwright.fonts.config.ts` kế thừa config chính). CI `visual.yml` job `compare` chạy `pnpm visual:test` (đã build web).

### API (chữ ký cần chốt)
```ts
// site.ts — tối thiểu, E5 mở rộng
export type Locale = "vi" | "en";
export type SiteContext = { tenantId: string; locale: Locale; themeId: string };

// define.ts
export type LocalizedText = { vi: string; en?: string };  // S02 thay bằng localized()
export type SectionMeta = {
  label: LocalizedText;
  icon: string;
  entitlement?: string;          // E6 thu hẹp thành Feature của packages/plans
  maxPerPage?: number;
  collections?: readonly string[];
};
export type SectionTypeDef<T extends string = string, S extends z.ZodType = z.ZodType> = {
  type: T; schemaVersion: number; schema: S; defaults: z.output<S>; meta: SectionMeta;
};
export function defineSectionType<const T extends string, S extends z.ZodType>(
  def: SectionTypeDef<T, S>,
): SectionTypeDef<T, S>;          // trả lại nguyên object, giữ kiểu literal

export type SectionPropsOf<D extends SectionTypeDef> =
  { data: z.output<D["schema"]>; site: SiteContext; sectionId: string };
export type SectionVariant<D extends SectionTypeDef> =
  (props: SectionPropsOf<D>) => React.ReactNode | Promise<React.ReactNode>;
export type VariantLoader<D extends SectionTypeDef> = () => Promise<{ default: SectionVariant<D> }>;

export type SectionVariants<D, V extends string> =
  { def: D; defaultVariant: V; variants: Record<V, VariantLoader<D>> };
export function defineVariants<D extends SectionTypeDef, const V extends string>(
  def: D, defaultVariant: NoInfer<V>, variants: Record<V, VariantLoader<D>>,
): SectionVariants<D, V>;
// dùng: defineVariants(calculator, "t12", { t12: () => import("./t12"), t14: () => import("./t14") })

// registry.ts
export function createRegistry<E extends Record<string, SectionVariants<any, string>>>(entries: E): {
  types: { [K in keyof E]: E[K]["def"] };
  getType(type: string): SectionTypeDef | undefined;
  getVariant(type: string, variant: string):
    { type: string; variant: string; fallback: boolean; load: VariantLoader<any> } | null;
};
export const sectionRegistry = createRegistry({ /* S04 thêm: hero, calculator… */ });
export type SectionTypeName = keyof typeof sectionRegistry.types;
export type SectionProps<K extends SectionTypeName> = SectionPropsOf<(typeof sectionRegistry.types)[K]>;
```
- Key của `entries` phải trùng `def.type` (kiểm ở runtime trong `createRegistry`: lệch → throw, có test).
- `getVariant`: variant có → `fallback: false`. Variant không có → trả variant mặc định, `fallback: true`,
  `console.warn("[sections] variant không tồn tại", { type, variant, fallback: defaultVariant })`. Type không có →
  `null` + `console.warn` (renderer S03 xử lý). Không throw để một section lỗi không làm sập trang.
- **Tránh vòng kiểu**: `SectionProps<K>` chỉ đọc `def` (không đọc kiểu của loader), nên variant `t12.tsx` có thể dùng
  `SectionProps<"calculator">` mà không tạo vòng `registry → index → t12 → registry`. Nếu TS vẫn báo vòng
  (`implicitly has type 'any'`), variant dùng `SectionPropsOf<typeof calculator>` (import từ `schema.ts`) và ghi vào
  "Lệch so với plan".
- `data` là `z.output` (sau parse, đã áp default của zod). `defaults` cũng là `z.output` — một test chung kiểm
  `def.schema.parse(def.defaults)` cho mọi type trong `sectionRegistry` (rỗng ở S01, có tác dụng từ S04).
- **Server Component + island**: variant mặc định là Server Component (không `"use client"`); variant được nạp bằng
  dynamic `import()` (loader) chỉ khi render; phần tương tác là file `"use client"` riêng, variant import bằng
  `next/dynamic` (giữ SSR — không `ssr: false`, nội dung vẫn hiện khi tắt JS theo AGENTS.md).

## Các bước
1. Tạo package `packages/sections` (package.json, tsconfig, tsconfig.test.json, eslint, scripts `typecheck`, `lint`,
   `lint:tokens`, `test`), `pnpm install` cập nhật lockfile — kiểm bằng: `pnpm --filter @solar/sections typecheck`.
2. `site.ts`, `define.ts`, `registry.ts`, `index.ts` theo Thiết kế — kiểm bằng: typecheck.
3. Test `node:test` `src/__tests__/registry.test.ts` (+ `fixtures.ts`, loader giả trả hàm thường, không `.tsx`):
   variant có → đúng loader, `fallback: false`, không warn; variant không có → loader mặc định, `fallback: true`,
   `console.warn` gọi đúng 1 lần với `{type, variant, fallback}` (dùng `mock.method(console, "warn")`); type không có →
   `null` + warn; key lệch `def.type` → throw; `defaults` của mọi type trong `sectionRegistry` parse được. —
   kiểm bằng: `pnpm --filter @solar/sections test`.
4. Kiểm kiểu AC1: `src/__tests__/types.typecheck.ts` (nằm trong `tsc --noEmit`, loại khỏi `tsconfig.test.json`) với
   `// @ts-expect-error` cho: variant đọc `data.khongCo`; variant sai kiểu trường (`data.title.toFixed()` khi là string);
   `defineVariants` nhận loader có props của type khác; `defaultVariant` không phải key của `variants`;
   `defaults` thiếu trường bắt buộc. Kèm 1 trường hợp đúng không có lỗi. — kiểm bằng: typecheck qua (nếu một
   `@ts-expect-error` không còn lỗi, tsc báo "Unused @ts-expect-error").
5. Trang lab `/lab/sections` + demo + thêm dependency/transpile vào `apps/web` — kiểm bằng: `pnpm --filter web typecheck`,
   `lint`, `lint:tokens`; `pnpm dev` mở trang thấy 2 section v1 + 1 section fallback, console có warn.
6. Spec `sections-bundle.spec.ts` + config + script + bước CI — kiểm bằng: `pnpm turbo run build --filter=web` rồi
   `pnpm --filter @solar/visual test:sections` qua. Chạy analyzer nếu có.
7. `packages/sections/README.md`; tick AC trong `roadmap/epics/E03-sections.md`.
