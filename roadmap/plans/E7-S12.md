## Thiết kế
- **Gỡ = xóa cứng**: giải phóng email để mời lại, cascade `SiteSession`/`SiteToken`, `Lead.assigneeId` SET NULL. Migration
  `20261030…_e7_s12_page_version_publisher` đổi FK sang `ON DELETE SET NULL ("publishedBySiteUserId")` + `schema.prisma` như `Lead`.
- `apps/admin/src/lib/staff.ts`: `createStaff({db, realm, limiter, now})` (cùng kiểu `createAccounts`, chuyển `createSiteInvite` sang đây) gồm
  `list, invite, resendInvite, changeRole, setLocked, remove, transferOwner, convertClient, convertToClient, sessions`.
- Mỗi hàm ghi: `authorize` → `tx()` = `withTenantTransaction(..., {isolationLevel:"Serializable"})` retry P2034 tối đa 3 lần (hết → 409
  "Dữ liệu vừa thay đổi"), P2002 → "đã có tài khoản". Trong tx đọc lại **actor và target**, kiểm luật, ghi, `auditLog` (`staff.invited|role_changed|locked|unlocked|removed|owner_transferred|client_converted|invite_resent`; không PII). Không `siteUser.update` ngoài tx.
- Luật chung `guard(actor, target)`: target là `client` với thao tác nhân viên → 404; target `owner` mà actor không owner → 403;
  target là chính mình → 400 (khóa/gỡ/đổi vai trò); hạ/khóa/gỡ owner active → cần còn owner active khác. Ghost: role owner, không `accountId`.
- Vai trò gán được: `admin|editor|staff|viewer` (zod chặn `owner`, `client`). Thu hồi phiên trong tx (như `accounts.ts:54`), mọi audience.
- Khóa chỉ áp cho `active`, mở chỉ cho `locked` (CAS `status`); khóa xóa cả token chưa dùng. Người `invited`: gửi lại/gỡ.
- Đếm limit: `role != client && status != disabled`, kể cả `invited`/`locked`. Subject đọc trong tx: `repo.site.first({include:{tenant:true}})`.
- Mời trùng client: owner nhận `{clientId}` + hỏi xác nhận đổi; admin nhận thông báo cần owner. Client → nhân viên cần `status=active`.
- `ActionResult` thêm `limit?: boolean`, `clientId?: string`; link SĐT dùng `url` sẵn có. `origin()` chuyển từ `app/actions.ts` sang `lib/auth.ts`.
- Actions `(admin)/nhan-vien/actions.ts`: `users.manage` (mời, gửi lại, vai trò, khóa, đổi client), `users.delete` (gỡ), `users.transferOwner`.
  Owner-only kiểm trong `staff.ts`. `logoutOtherSessions` trong `(admin)/tai-khoan/bao-mat/actions.ts` quyền `account.totp` (ghost bị loại sẵn).
- UI: `StaffManager.tsx` (client) theo mẫu `LeadChannels`; page gate `users.view` trước query, không `users.manage` → chỉ đọc; nút hiện theo permission/role nhưng server vẫn kiểm. `totpSecret` đổi thành boolean trong `list`. `h1` bảo mật đổi "Bảo mật tài khoản", thêm mục phiên.
- `realm.completeLogin`: ghi `lastLoginAt` qua `updateAccount` sau `createSession`; `AccountPatch` thêm trường, `platformStore` bỏ qua. Lỗi ghi không chặn login.
- Nhãn audit `staff.*` thêm vào bảng nhãn `apps/admin/src/lib/dashboard.ts:50`.
- `upgradeSchema` nhận `limit:users`, handler bỏ kiểm `available`; `UpgradeRequest` hiện `limitLabels.users`. `setPassword` invite: `emailVerifiedAt` chỉ set khi có email.
