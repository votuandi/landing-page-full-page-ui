## Mục tiêu
Mọi tiến trình `web` dùng chung trạng thái vô hiệu hóa cache qua Redis: xuất bản ở một instance → mọi instance phục vụ bản
mới ở request kế tiếp; render dở/restart Redis/mất pub/sub không làm lộ bản cũ; Redis chết thì site vẫn chạy.

## Bối cảnh đã khảo sát
- `packages/cache/src/memory.ts` — L1 bộ nhớ (TTL, LRU, single-flight, identity chống ghi đè); `index.ts` tạo singleton
  ngay lúc import (worker và `packages/db` cũng import `@solar/cache`).
- Data cache dùng ở `apps/web/src/lib/tenant/siteData.ts:89,107` và `collections.ts:29`; giá trị là object JS (Date, theme…)
  → **không** tuần tự hóa lên Redis.
- `"use cache"` ở `apps/web/src/components/tenant/cached.tsx:41,62`, `TENANT_CACHE_LIFE = {stale 60, revalidate 60, expire 86400}`
  (`cacheTags.ts:15`); `next.config.ts` bật `cacheComponents`, chưa có `cacheHandlers`.
- `revalidate.ts:69-70` gọi `invalidate(tags)` rồi `revalidateTag(tag, {expire:0})`; Redis lỗi → 503 (worker retry).
- `redis.ts` (host resolver): mẫu 2 kết nối ioredis, `autoResubscribe:false`, mất kết nối → xóa toàn bộ cache cục bộ.
- Next 16.3.8: handler `cacheHandlers` được `import()` lúc chạy theo đường dẫn (không bundle) → phải là JS chạy được trên
  Node 20 (local) và 22 (Docker). `use-cache-wrapper.js:733,809` đặt `entry.timestamp = startTime` (lúc **bắt đầu** render);
  `:2433` tự kích revalidate nền khi `now > timestamp + revalidate*1000`.
- `prerender-manifest.json`: chỉ trang tĩnh lúc build (legacy, `/lab/*`, robots, `revalidate:false`); route tenant động.
- Truy vấn: `codegraph explore "cached invalidate createMemoryCache"`, grep `@solar/cache|ioredis|cacheHandler|use cache`.

## Quyết định đã chốt với người dùng
- Giữ một story. **Không** cấu hình `cacheHandler` (ISR): không nội dung tenant nào đi qua incremental cache; handler tùy biến
  không đọc được bản build → render lại trang tĩnh vô ích. Ghi lý do vào epic (sửa dòng Chi tiết) + README `packages/cache`.

## Thiết kế
1. **Lõi JS** `packages/cache/src/redis.js` (ESM, `// @ts-check` + JSDoc; base tsconfig có `allowJs` — thêm `checkJs`,
   `include` `src/**/*.js`). Lý do JS: Next nạp handler bằng `import()` nguyên file; tránh bước build/dist. Export subpath
   `"./redis": "./src/redis.js"`; thêm `ioredis 5.10.0` vào `dependencies` của `@solar/cache` (đã chấp thuận ở AGENTS.md).
   `createRedisCore(url, { now, skewMs = 1000, log })` — singleton qua `globalThis[Symbol.for("solar.cache.redis")]` để handler
   (nạp native) và code app (bundle) dùng chung kết nối:
   - Kết nối command (`enableOfflineQueue:false, maxRetriesPerRequest:0, commandTimeout:300`) + subscriber kênh `cache:invalidate`.
   - **Tag clock**: `invalidate(tags)` = Lua `SET tag:<t>:invalidatedAt max(cũ, now+skewMs)` + `PEXPIRE 8 ngày` (> expire
     dài nhất 24 h) cho mọi tag, rồi `PUBLISH`. `expiration(tags)` = `MGET` → max, và **không nhỏ hơn `floor`**.
   - **floor** = thời điểm Redis khởi động (`INFO server` → `now − uptime_in_seconds*1000 + 1000`), đọc lại mỗi lần `ready`.
     Mọi entry bắt đầu trước floor coi như hết hạn → bản RDB khôi phục/render vắt qua restart không được phục vụ.
   - Sự kiện `close`/`error`/`ready` của 2 kết nối và subscribe lại → gọi listener `onReset` (xóa L1). Pub/sub chỉ để xóa sớm.
   - `warn()` ghi `console.warn("[cache] Redis unavailable …")` tối đa 1 lần/60 s, không in URL/secret.
2. **Data cache** `createRedisContentCache({ core, memory })` trong `packages/cache/src/shared.ts`: L1 = `createMemoryCache`
   (giữ nguyên), entry thêm `startedAt`. Đọc hit → `core.expiration(entry.tags)`; `startedAt <= expiration` → bỏ entry, render
   lại. Lỗi Redis → gọi `fn()` trực tiếp (không cache, `warn`). `invalidate` = xóa L1 cục bộ + `core.invalidate` (lỗi → ném,
   giữ hành vi 503 của endpoint). Tin pub/sub → xóa L1 theo tag; `onReset` → xóa toàn bộ L1.
   `index.ts`: tạo cache **lười** ở lần gọi `cached`/`invalidate` đầu tiên: `REDIS_URL` → Redis, không → memory (dev).
3. **Handler `"use cache"`** `apps/web/cache-handler.mjs` (glue nhỏ) + `createUseCacheHandler(core)` trong `redis.js`;
   `next.config.ts` `cacheHandlers: { default: <đường dẫn tuyệt đối> }` luôn bật (biến môi trường lúc build không có
   `REDIS_URL`); handler tự chọn lúc chạy: không `REDIS_URL` → `next/dist/server/lib/cache-handlers/default.external.js`.
   - Lưu hash `uc:<sha256(key)>` {meta JSON (tags, stale, timestamp, expire, revalidate), value bytes}, `PEXPIRE expire`.
   - `get(key, softTags)`: hợp lệ ⇔ `timestamp > expiration(tags ∪ softTags)` và `now < timestamp + expire*1000`.
     Tươi → trả. **Cũ nhưng hợp lệ** (quá revalidate): giành khóa `lock:<hash>` (`SET NX PX 15000`, token) — được → trả nguyên
     (Next render nền); không được → trả bản sao có `revalidate` nới tới hiện tại (Next không render thêm). **Không hợp lệ**:
     được khóa → `undefined` (render); không → chờ entry mới (poll 50 ms, ≤ 5 s) rồi trả, hết giờ → `undefined`.
   - `set(key, pending)`: đọc hết stream (lỗi stream → bỏ), ghi, nhả khóa bằng Lua so token. Lỗi Redis → bỏ qua + `warn`.
   - `getExpiration(tags)` → `core.expiration`; lỗi → `Infinity` (để `get` quyết, `get` lỗi trả `undefined`).
   - `updateTags(tags)` → `core.invalidate(tags)` (mọi `durations` coi như expire ngay). `refreshTags` no-op.
4. Endpoint revalidate giữ nguyên code; README: có `REDIS_URL` thì `WEB_REVALIDATE_URLS` chỉ cần một URL bất kỳ.
