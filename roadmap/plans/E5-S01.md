## Mục tiêu
Có package `@solar/db` (Prisma 7 + Postgres 16) với schema đủ cho nền tảng nhiều khách: nền tảng, site/page/section,
collection, media, lead, outbox, audit, plan. Mọi bảng tenant có `tenantId` và khóa ngoại ghép `(tenantId, xxxId)` nên
dữ liệu của A không thể trỏ sang B. Migration đầu tiên + seed 2 tenant demo (t15, t12, trùng slug) chạy được; có test
chặn tham chiếu chéo tenant và ERD.

### Quy ước schema
- Id: `String @id @default(uuid(7)) @db.Uuid`, trừ `Plan.id` (`"basic" | "pro" | "premium"`, text).
- `createdAt @default(now())`, `updatedAt @updatedAt` ở bảng có sửa.
- **Bảng tenant** (mọi bảng trừ `Tenant`, `User`, `PlatformAdmin`, `Plan`): cột `tenantId` (FK → `Tenant.id`,
  `onDelete: Cascade`), `@@unique([tenantId, id])`, index bắt đầu bằng `tenantId`.
- **Khóa ngoại giữa bảng tenant luôn ghép**: `@relation(fields: [tenantId, xxxId], references: [tenantId, id])`. Không
  có quan hệ nào giữa hai bảng tenant chỉ theo `id`.
- Trường localizable = `Json` (`{ vi, en? }`); phần còn lại của item collection nằm trong `data Json` (kiểm bằng zod của
  `collectionSchemas` khi ghi — repository E5-S02/CMS E7). Enum dùng `enum` của Prisma.

### Model (tối thiểu cần có; được thêm cột tùy chọn nếu cần cho 15 preset, ghi vào report)
- **Nền tảng**
  - `Plan` { id, name, features String[], limits Json, syncedAt } — seed chèn `basic|pro|premium` tạm (E6-S01 đồng bộ).
  - `Tenant` { id, name, slug unique, status `trial|active|suspended`, planId → Plan, addons String[] }.
  - `User` { id, email unique (lưu chữ thường), name?, passwordHash?, createdAt } — E7-S01 có thể mở rộng.
  - `Membership` { tenantId, userId → User, role `owner|editor|viewer` } `@@unique([tenantId, userId])`.
  - `PlatformAdmin` { id, userId unique → User, createdAt }.
  - `Domain` { tenantId, siteId (ghép → Site), hostname **unique toàn cục** (lưu đúng host, chữ thường, không cổng),
    isPrimary, status `pending|verified|active|error|removed`, verificationToken, verifiedAt?, sslProvider
    `caddy|cloudflare`, cfHostnameId? }. Index `(tenantId, siteId)`.
- **Site**
  - `Site` { tenantId, name, themeId, presetId?, themeOverrides Json default `{}`, locales String[] default `["vi"]`,
    defaultLocale default `"vi"`, profile Json default `{}` (thông tin công ty kiểu `CompanyInfo`: tên, logo mediaRef,
    slogan, liên hệ, mạng xã hội), widgets Json default `{}`, seo Json default `{}` }.
  - `Page` { tenantId, siteId (ghép), slug, kind `home|landing|system`, title Json?, sections Json (mảng
    `{ id, type, variant, enabled, anchor?, layout? }` — **không** chứa data), draftSections Json?, revision Int default 0,
    publishedAt? } `@@unique([tenantId, siteId, slug])`.
  - `PageVersion` { tenantId, pageId (ghép), revision, snapshot Json (sections + nội dung section), publishedById? →
    User, createdAt } `@@unique([tenantId, pageId, revision])`.
  - `SectionContent` { tenantId, siteId (ghép), pageId (ghép), sectionId String (id trong `Page.sections`; nhân bản trang
    thì sinh UUID mới — story sau), type, schemaVersion Int, data Json, draftData Json?, revision Int default 0 }
    `@@unique([tenantId, pageId, sectionId])`.
- **Collection** (`Product`, `ProductCategory`, `Project`, `Story`, `Post`, `Faq`, `Testimonial`, `Branch`, `Certificate`,
  `Brand`, `PressItem`, `Service`) — cột chung: tenantId, slug, status `draft|published` default `draft`, order Int
  default 0, title Json (localizable; Faq = câu hỏi, Testimonial = tên khách), data Json default `{}`, publishedAt?,
  createdAt, updatedAt; `@@unique([tenantId, slug])`, `@@index([tenantId, status, order])`. Cột có cấu trúc để lọc/sắp xếp:
  - `Product`: categoryId? (ghép → ProductCategory), brandId? (ghép → Brand), price Int?, salePrice Int?, featured
    Boolean default false, segments String[].
  - `ProductCategory`: parentId? (ghép → ProductCategory).
  - `Project`: segment String?, kwp Float?, featured Boolean, coverMediaId? (ghép → Media).
  - `Story`: segment String?, kind String?, posterMediaId? (ghép → Media).
  - `Post`: segment String?, coverMediaId? (ghép → Media), tags String[].
  - `Faq`: group String?. `Testimonial`: segment String?, rating Float?. `Branch`: isPrimary Boolean.
  - `Brand`: logoMediaId? (ghép → Media). `Certificate`, `PressItem`, `Service`: chỉ cột chung.
- **Khác**
  - `Media` { tenantId, key **unique toàn cục** (dạng `tenants/<tenantId>/…`), driver `local|s3`, visibility
    `public|private`, status `quarantine|ready|failed`, mime, size Int, width?, height?, variants Json?, alt Json?,

  - `Lead` { tenantId, siteId? (ghép), source, segment?, name?, phone, email?, message?, data Json, status

  - `Outbox` { tenantId? (null = việc nền tảng; khi có thì FK → Tenant), topic, payload Json, idempotencyKey unique,

  - `LeadIntegration` { tenantId, kind `webhook|google_sheets|telegram`, name, enabled, configEncrypted String (bản mã),
    createdAt, updatedAt }.
  - `AuditLog` { tenantId? (FK → Tenant khi có), actorUserId? → User, action, entity, entityId?, data Json?,
    createdAt } index `(tenantId, createdAt)`.
- Quan hệ chiều ngược (`Tenant.products` …) khai báo đủ để Prisma hợp lệ; không thêm quan hệ ngoài danh sách.

### `assertRefsBelongToTenant`
```ts
export type TenantRefs = {
  media?: string[];                                             // mediaRef.id; id bắt đầu bằng "/" (ảnh tĩnh) bị bỏ qua
  collections?: Partial<Record<CollectionName, string[]>>;      // collectionQuery.ids
};
export type CollectionName = "projects" | "stories" | "testimonials" | "posts" | "products" | "branches"
  | "faqs" | "brands" | "certificates" | "press" | "services" | "productCategories";
export class CrossTenantRefError extends Error { readonly missing: { kind: string; ids: string[] }[] }
export async function assertRefsBelongToTenant(db: Pick<PrismaClient, ...> | Prisma.TransactionClient,
  tenantId: string, refs: TenantRefs): Promise<void>
```
- Gom id duy nhất theo loại; id không phải UUID hợp lệ → coi như thiếu (không gửi xuống DB, tránh lỗi ép kiểu uuid);
  `findMany({ where: { tenantId, id: { in } }, select: { id: true } })`; thiếu id nào → ném `CrossTenantRefError` liệt kê
  đủ. Rỗng → không truy vấn. Việc rút ref từ dữ liệu section theo schema zod thuộc E5-S02 (repository khi ghi).

### Ràng buộc chéo tenant khi `connect` lồng nhau
- Quyết định Claude sau kiểm tra Postgres 16: FK ghép không đủ cho nested connect. Prisma có thể lấy `tenantId` từ
  category/media/page được connect và INSERT toàn bộ vào tenant khác. `createDb()` phải trả client `$extends` với
  query extension gọi hàm thuần `assertNoCrossTenantConnect(model, operation, args)` trong `src/tenantGuard.ts`.
- Kiểm `create`, `createMany`, `update`, `updateMany`, `upsert` (và các biến thể `*AndReturn` có cùng khả năng ghi).
  Xác định tenant từ `data.tenantId`, `data.tenant.connect.id`, `where.tenantId`, `where.tenantId_id.tenantId`; các nguồn
  có mặt phải khớp nhau. Upsert kiểm cả create và update. Nested writes dưới `Tenant` lấy tenant từ `data.id`/`where.id`.
- Duyệt đệ quy đúng các trường relation của schema, không duyệt JSONB. Mọi `connect`, `connectOrCreate.where`, `set`
  tới model tenant phải có `tenantId_id` cùng tenant đang ghi. Selector chỉ `{ id }`, tenant khác hoặc không xác định
  được tenant đang ghi → `CrossTenantRefError`. Kiểm từng selector trong mảng.
- Nested `create`/`createMany` kế thừa tenant cha; tenant con ghi rõ phải khớp. Duyệt cả nested update/upsert để không
  bỏ lọt connect sâu. `tenant: { connect: { id } }` phải khớp tenant đang ghi.
- Quan hệ tới model toàn cục (`User`, `Plan`, `Tenant`, `PlatformAdmin`) cho phép selector thông thường, ngoài quy tắc
  riêng cho trường `tenant`. Giữ danh sách trường relation toàn cục ở một chỗ; `schema.test.ts` đối chiếu mọi relation
  với `schema.prisma`, buộc quan hệ mới được phân loại.
- Unit test hàm thuần không cần DB; integration dùng `createDb`, chặn Product.category, Project.coverMedia,
  SectionContent.page chéo tenant và xác nhận 0 dòng ở cả A/B; nested `tenant.update` cũng phải chặn.
  Connect cùng tenant bằng `tenantId_id` vẫn chạy, kể cả trong transaction. Seed dùng connect phải theo quy tắc này.

- Chạy lại nhiều lần không lỗi, không nhân đôi: upsert theo khóa tự nhiên (`Plan.id`, `Tenant.slug`, `Domain.hostname`,

- Plans: `basic`, `pro`, `premium` (features rỗng, limits `{}`) — tạm.
