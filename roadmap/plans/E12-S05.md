# Plan E12-S05 — Tùy chọn bố cục có giới hạn

## Mục tiêu
Mỗi section instance có `layout` (nền, khoảng cách, căn chỉnh, ẩn theo thiết bị) + sửa `anchor` trong builder; mọi tùy chọn
chỉ ra class/biến token có sẵn; variant khai báo tùy chọn nó hỗ trợ, tùy chọn không hỗ trợ bị ẩn (UI) và bỏ qua (render).

## Bối cảnh đã khảo sát
- `packages/sections/src/page.ts` `pageSectionSchema` đã có `anchor` (regex `^[a-z0-9-]+$`, unique trong `pageConfigSchema`)
  → story dùng `anchor` làm `anchorId`, không thêm trường trùng.
- `PageRenderer` bọc mỗi section bằng `<div id={anchor} data-section-id …>`; variant tự đặt nền + padding trên `<section>`
  gốc (`bg-bg`, `bg-bg-elevated`, `t15-section` = `min-h-section py-16 md:py-24`…) → nền/khoảng cách cần variant phối hợp.
- `CONTRAST_PAIRS` (tokens) đã bảo đảm AA cho `fg|fg-muted|fg-subtle` trên `bg|bg-elevated|bg-tint|bg-sky|bg-sun` ở mọi theme.
  `bg-deep` thì không (t15 tối, t08 sáng) → `deep`/`invert` làm bằng **đổi bảng màu theo vùng**, không đặt `bg-bg-deep`.
- `themeToCss`: `[data-theme="dark"]{dark}` chỉ khi `meta.supportsDark`. Sections không dùng `dark:`, Tailwind không cấu hình darkMode.
- Lưu descriptor: `descriptorSchema = pageSectionSchema.omit({data}).strict()` (admin) và `descriptors()` (db) → thêm trường
  vào `pageSectionSchema` là lưu/đọc được. `saveDraft` → `checkStructure` → `validateSiteStructure` (D21).
- Builder (`apps/admin/…/builder/Builder.tsx`, `BuilderPanel.tsx`) lưu descriptor qua `saveSectionsDraft` + `queue.write` (như `reorder`).
- `findHardcoded` (`tooling/eslint-plugin/src/matchers.mjs`) là lõi của `lint:tokens`; `packages/sections` đã có devDep `@solar/eslint-plugin`.
- Truy vấn: `codegraph explore "section instance layout background spacing anchorId hideOn"`, `codegraph sync`.

## Thiết kế
1. **`packages/sections/src/layout.ts`** (mới, export qua `index.ts`):
   `sectionLayoutSchema = z.strictObject({ background?: z.enum(["default","tint","sky","sun","deep","invert"]), spacing?: z.enum(["compact","normal","loose"]), align?: z.enum(["start","center"]), hideOn?: z.enum(["mobile","desktop"]) })`;
   `type LayoutCapability = "background" | "spacing" | "align"` (hideOn + anchor luôn có — do wrapper xử lý);
   `resolveLayout(layout, caps): SectionLayout | undefined` bỏ key không hỗ trợ và giá trị mặc định;
   `wrapperLayout(layout) → { className?, "data-surface"? }`; `surfaceClass(bg, fallback)`, `spacingClass(sp, fallback)`
   trả **chuỗi literal** (Tailwind quét được); `LAYOUT_CLASSES` = mọi class helper có thể trả (cho test AC1).
   Map: tint→`bg-bg-tint`, sky→`bg-bg-sky`, sun→`bg-bg-sun`, deep/invert→ giữ nền variant + wrapper `data-surface` + `bg-bg text-fg`.
   Lỗi nó ngăn: `bg-bg-deep` trên theme sáng/tối khác nhau làm chữ mất tương phản; vùng màu đổi **mọi** token con cùng lúc.
2. `page.ts`: `layout: sectionLayoutSchema.optional()`. Không `.catch` — dữ liệu chỉ vào qua save đã validate.
3. **Khai báo hỗ trợ**: `defineVariants(def, default, variants, layout?: Partial<Record<V, readonly LayoutCapability[]>>)`;
   registry thêm `layoutOf(type, variant): readonly LayoutCapability[]` (theo variant đã resolve fallback, mặc định `[]`).
4. **Render**: `PageRenderer` tính `layout = canUse("builder") ? resolveLayout(section.layout, registry.layoutOf(...)) : undefined`;
   wrapper nhận `wrapperLayout`; variant nhận prop `layout` (thêm `layout?: SectionLayout` vào `SectionPropsOf`).
   `hideOn` ẩn bằng class wrapper (`max-md:hidden`/`md:hidden`) — không JS, SSR đúng; builder preview cũng ẩn (WYSIWYG theo khung).
5. **Variant opt-in** (chỉ thay class nền/padding của `<section>` gốc bằng helper, không đổi bố cục khác):
   faq t15/t02/t05/t10 (`background`,`spacing`); trust/t11, segments/t11, projects/t11, services/t02, blog/minwy,
   brands/minwy, products/minwy (`background`,`spacing`); `align` cho ≥ 1 variant có khối tiêu đề đơn (vd. services/t02, faq/t02).
   Không opt-in variant nền ảnh/gradient/`bg-primary|accent` (hero, cta-banner, stats/t15…).
6. **CSS vùng màu** (`packages/tokens/src/css.ts`, chỉ khi `supportsDark`): chỉ khai báo **màu** (light/dark + override tenant đã có),
   `color-scheme` tương ứng; có `scope` thì thêm tiền tố scope như khối dark hiện có.
7. **Luật gói** (`packages/presets/src/structure.ts`): `StructureSection` thêm `layout?`; trong vòng section: `!can("builder")`
   và `JSON(layout ?? {}) !== JSON(original section cùng id ?.layout ?? {})` → issue `Gói không cho tùy chỉnh bố cục section: /<slug>`.
   So bằng chuỗi JSON đã chuẩn hóa thứ tự key (helper `layoutKey`) — tránh báo sai khi key đổi thứ tự.
8. **Admin**: `EditableSection` thêm `layout?`; `LayoutFields.tsx` (mới, trong `builder/`) render trong `BuilderPanel` dưới tiêu đề,
   ngoài fieldset nội dung; props `{ section, themeSupportsDark, sections, disabled, onChange(next: EditableSection) }`.
   Builder: `changeLayout(next)` = bản sao logic `reorder` (cập nhật lạc quan, `queue.write` → `saveSectionsDraft`, lỗi → hoàn nguyên +
   `resultError`, ok → `refresh()`). `loadBuilder` trả thêm `themeSupportsDark` (`getTheme(themeId)?.meta.supportsDark`).
   Quyền sửa = `editor.canReorder` (pages.structure + gói); không có → control `disabled`.
   Logic lọc tùy chọn thuần nằm trong `apps/admin/src/lib/layoutOptions.ts` (`layoutOptions(type, variant, supportsDark)`, `anchorError(value, sections, id)`) để unit test.
   Mã neo: lưu khi blur/Enter nếu hợp lệ; rỗng → xóa `anchor`.
9. `tooling/eslint-plugin/package.json` exports thêm `"./matchers": "./src/matchers.mjs"` cho test AC1.

## Hợp đồng e2e
- Panel: `getByRole("group", { name: "Bố cục" })` (fieldset legend "Bố cục"); `<select>` với label đúng: "Nền", "Khoảng cách",
  "Căn chỉnh", "Ẩn trên"; option `value` = giá trị enum (`default` = "Mặc định", `""` cho "Ẩn trên" = "Không ẩn"); input `getByLabel("Mã neo")`.
- Canvas: wrapper `main [data-section-id="s-faq"]` mang `data-surface`, class `max-md:hidden`/`md:hidden`, `id` = anchor; `<section>` con mang `bg-bg-tint`.
- Lỗi mã neo: `role="alert"` trong group "Bố cục", chữ "Mã neo đã dùng" / "Chỉ dùng chữ thường, số và dấu gạch nối".
