## Mục tiêu
Package mới `@solar/tokens` có zod schema `ThemeTokensSchema`, kiểu `ThemeTokens` và hàm `parseTheme()` — kiểu dữ liệu
duy nhất mô tả một theme. Theme t15 hiện tại (khối `:root` / `[data-theme="dark"]` trong `apps/web/src/app/globals.css`
+ font/bo góc/motion đang rải trong preset Tailwind, `layout.tsx`, CSS) biểu diễn được trọn vẹn bằng schema. Lỗi parse
nêu rõ đường dẫn trường và lý do.

`src/schema.ts` (export):
- `COLOR_KEYS` — mảng `as const` 35 khóa kênh RGB, tên kebab-case **trùng tên biến CSS** (`"bg-elevated"`, `"skin-shade"`…):
  `bg, bg-elevated, bg-deep, bg-tint, bg-sky, bg-sun, primary, primary-strong, primary-deep, secondary, secondary-deep, leaf,
  sky, accent, accent-soft, accent-ink, on-primary, on-secondary, on-accent, on-media, fg, fg-muted, fg-subtle, line, scrim,
  shadow, success, danger, chart-a, chart-b, skin, skin-shade, skin-light, device, glass-tint`.
- `GLASS_COLOR_KEYS` — `["glass", "glass-border", "glass-strong", "glass-strong-border"]` (giá trị rgba).
- `RgbChannels` = string `"R G B"`: regex `^\d{1,3} \d{1,3} \d{1,3}$`, mỗi kênh 0–255 (refine). Thông báo:
  `phải có dạng "R G B" (0–255), vd. "21 128 61"`.
- `RgbaColor` = string `rgba(R,G,B,A)` (cho phép khoảng trắng, A trong [0,1], R/G/B 0–255). Thông báo:
  `phải có dạng rgba(R,G,B,A), vd. rgba(255,255,255,0.78)`.
- `ColorSetSchema` = `z.strictObject` gồm mọi `COLOR_KEYS` → `RgbChannels` và `GLASS_COLOR_KEYS` → `RgbaColor`, tất cả bắt buộc.
- `ThemeTokensSchema` = `z.strictObject({...})`:
  - `colors: { light: ColorSetSchema, dark: ColorSetSchema.partial().optional() }` — dark là ghi đè, token thiếu kế thừa light.
  - `font: { sans: string≥1, display: string≥1, weights: number[] (≥1 phần tử, mỗi số nguyên 100–900 bội 100, không trùng),
    source: "google" | "local" }`.
  - `radius: { card, pill, media, input, button }` — chuỗi độ dài CSS `^\d+(\.\d+)?(px|rem)$`.
  - `shadow: { strength: number 0–1, tint: enum COLOR_KEYS }` (token màu dùng pha bóng; t15 = `"shadow"`).
  - `glass: { blur: số nguyên px 0–64, enabled: boolean }`.
  - `motion: { durationFast, durationBase, durationSlow: số nguyên ms 0–5000, easing: string≥1, revealDistance: số px 0–200,
    revealEnabled: boolean }`.
  - `density: { sectionY: "sm" | "md" | "lg", container: số nguyên px 640–1920 }`.
  - `meta: { id: ^[a-z0-9]+(-[a-z0-9]+)*$, name: string≥1, group: "classic" | "pro" | "signature", supportsDark: boolean,
    preview?: string≥1 (đường dẫn/URL ảnh) }`.
  - Mọi object con dùng `strictObject` → trường lạ (gõ sai tên) bị báo lỗi.
  - `superRefine`: `meta.supportsDark === true` ⇔ có `colors.dark`; sai → lỗi ở `colors.dark` (hoặc `meta.supportsDark`).
- `type ThemeTokens = z.infer<typeof ThemeTokensSchema>`, `type ColorKey = typeof COLOR_KEYS[number]`, `type ColorSet`.
- `class ThemeParseError extends Error` có `issues: { path: string; message: string }[]` (path nối bằng `.`, vd.
  `colors.light.primary`). `message`: `Theme "<meta.id hoặc ?>" không hợp lệ:` + mỗi issue một dòng `- <path>: <lý do>`.
  Lý do tiếng Việt: thiếu trường (`invalid_type` với input `undefined`) → `thiếu trường bắt buộc`; trường lạ
  (`unrecognized_keys`) → `trường không được hỗ trợ: <keys>`; còn lại dùng message tùy biến ở trên hoặc message của zod.
- `parseTheme(input: unknown): ThemeTokens` — `safeParse`, lỗi → throw `ThemeParseError`.
- `safeParseTheme(input: unknown)` → `{ ok: true, theme } | { ok: false, error: ThemeParseError }` (CMS E7 dùng để hiện lỗi
  không cần try/catch).

Fixture t15 (`src/__tests__/fixtures/t15.ts`): chép đúng giá trị khảo sát ở trên — light đủ 35 + 4 glass; dark đúng các biến
có trong khối `[data-theme="dark"]` (kể cả 4 glass, glass-tint); `font` Be Vietnam Pro ×2 / [400,600,800] / google;
`radius` card 28px, pill 9999px, media 32px, input 16px, button 9999px; `shadow` strength 1, tint "shadow"; `glass`
blur 24, enabled true; `motion` 300/500/900, `cubic-bezier(.16,1,.3,1)`, 64, true; `density` md / 1280;
`meta` id `t15`, name `Fresh Energy`, group `signature`, supportsDark true. Gắn comment `[DỮ LIỆU MẪU]` không cần (đây là token
thật của t15, không phải dữ liệu khách). E2-S07 sẽ chuyển fixture này thành `packages/themes/t15/theme.ts`.

## Các bước
1. Tạo package `packages/tokens` (package.json, tsconfig*, eslint.config.mjs, README.md, src/index.ts) theo mẫu `packages/core`;
   `pnpm install` để cập nhật `pnpm-lock.yaml` (zod 4.6.5). Script `test`: `tsc -p tsconfig.test.json && node --test
   .test-dist/__tests__/schema.test.js`. — kiểm bằng: `pnpm --filter @solar/tokens typecheck`.
2. Viết `src/schema.ts` theo Thiết kế. — kiểm bằng: typecheck + lint.
3. Viết fixture t15 + `schema.test.ts` (node:test), các ca:
   a. t15 parse thành công và kết quả `deepEqual` input (không mất/biến đổi trường).
   b. **Đối chiếu globals.css**: đọc `apps/web/src/app/globals.css` (đường dẫn từ `process.cwd()` = thư mục package:
      `../../apps/web/src/app/globals.css`), lấy mọi `--c-<tên>: R G B` và 4 biến glass trong khối light và khối dark
      (cắt khối theo selector `:root, [data-theme="light"] {` và `[data-theme="dark"] {` đầu tiên, tới `}`), so khớp
      khóa + giá trị với fixture `colors.light` / `colors.dark`. Chứng minh Target "không mất biến nào".
      (E2-S07 xóa khối `:root` sẽ xóa/đổi ca này — ghi chú trong test.)
   c. Xóa `colors.light.primary` → `parseTheme` throw `ThemeParseError`, `issues` có path `colors.light.primary`, message
      chứa `colors.light.primary` và `thiếu trường bắt buộc`.
   d. Sai định dạng: `primary: "21,128,61"` và `"21 128 300"` bị từ chối với path đúng; `glass: "#fff"` bị từ chối.
   e. Trường lạ `colors.light.primry` → lỗi `trường không được hỗ trợ`.
   f. `supportsDark: true` mà không có `dark` → lỗi; `supportsDark: false` không có `dark` → hợp lệ.
   g. `dark` thiếu nhiều token (partial) → hợp lệ.
   h. Biên giá trị: `shadow.strength: 1.2`, `font.weights: [450]`, `radius.card: "28"`, `meta.group: "gold"` → lỗi với path đúng.
   i. Nhiều lỗi cùng lúc → `issues` liệt kê đủ (≥ 2), không dừng ở lỗi đầu.
   j. `safeParseTheme` trả `{ ok: true }` / `{ ok: false, error }` tương ứng.
   — kiểm bằng: `pnpm --filter @solar/tokens test`.
4. Tick 2 AC của E2-S01 trong `roadmap/epics/E02-tokens-themes.md`.

## Rủi ro / câu hỏi mở
- [không chặn] `dark` toàn phần hay một phần → chọn **một phần** (ghi đè), vì t15 dark chỉ ghi đè một số token; bắt toàn phần
  sẽ buộc chép giá trị light vào dark và lệch với CSS hiện tại.
- [không chặn] Tên khóa màu kebab-case thay vì camelCase → trùng tên biến CSS, E2-S02/S03 sinh `--c-<key>` trực tiếp.
- [không chặn] `shadow.tint` là tên token màu (enum) thay vì giá trị RGB → không trùng lặp dữ liệu với `colors.shadow`;
  override màu của khách tự áp vào bóng.
- [không chặn] Đơn vị: thời lượng là số ms, blur/khoảng cách/container là số px; bo góc là chuỗi CSS (cần `9999px`, `rem`).
- [không chặn] zod 4 biên dịch CommonJS cho test (`tsconfig.test.json` module commonjs) — zod 4.6.5 có bản CJS; nếu
  `node --test` lỗi import thì báo trong report, không đổi sang ESM tùy tiện.
