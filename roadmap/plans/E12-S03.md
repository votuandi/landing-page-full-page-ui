## Thiết kế
**Thư viện (cms-ui, thuần).** `packages/cms-ui/src/sections/library.ts`:
`LIBRARY_GROUPS = [{ id, label, types }]` — Mở đầu: site-header, hero, page-hero, segments · Thuyết phục: stats, projects,
testimonials, trust, press, brands, shorts, tiktok, about-story · Chuyển đổi: calculator, lead-form, packages, cta-banner, dealer,
investment-models · Nội dung: services, process, products, energy-monitoring, load-profile, warranty, faq, blog, branch-map, social ·
Chân trang: site-footer. Map ở cms-ui thay vì thêm `meta.group` vào 30 schema → ít file, test R3 bắt type mới.
`libraryStatus(type, sections, allowedTypes, lockedTypes): { kind: "ok" } | { kind: "locked"; reason: "Cần nâng cấp gói" } | { kind: "limit"; reason }`
(reason = `sectionLimitIssues([...sections, { type }])[0]`) → một nguồn lý do cho nút, kéo và hàm thêm.
`ops.ts`: `insertRelative(value, section, targetId?, position?)` — id trùng → trả nguyên; target thiếu/lạ → cuối; không có
`targetId` → cuối. `export newSectionId`.

**Protocol** (`protocol.ts`, parser nghiêm như `reorder`): lệnh admin → iframe `drag { y }`, `drop { y }`, `drag-cancel`;
`y` số hữu hạn 0…100000 (px viewport iframe), sai → null. Sự kiện iframe → admin `insert { targetId?, position? }`: có cả hai
hoặc không có cái nào. Admin chỉ gửi tọa độ, iframe quyết định target như khi reorder → bỏ qua section ẩn/khóa, header/footer
(không nằm trong `main`) giống hệt kéo nội bộ.
`PreviewFrame`: prop `handle?: Ref<{ post(command): void }>` (`useImperativeHandle`), chỉ gửi khi đã `ready`; thêm `insert` vào
danh sách sự kiện chuyển cho `onEvent`.

**Phía iframe.** `builderMode.ts`: `dropTarget(rects, y, excludeId?) → { targetId, position, top } | null` (tách từ `calculate`,
dùng cho cả kéo nội bộ và ngoài). `BuilderCanvas` nhận prop `handle` (không dùng `ref` qua `next/dynamic`): `dragAt(y)` tạo drag
ngoài (`id: ""`, `pointerId: -1`, `moved: true`, `handle` tùy chọn) → hiện đường chèn + tự cuộn mép bằng `tick` sẵn có;
`drop(y)` → trả target rồi hủy; `cancel()`. `PreviewBridge` chuyển 3 lệnh vào handle chỉ khi `mode.reorder`; `drop` → gửi `insert`.
Đường chèn có `data-builder-drop`.

**Phía admin.**
- `loadBuilder` thêm `themeId`, `allowedTypes`, `lockedTypes`; tách helper `typeAccess(can)` dùng chung với `loadPageEditor`.
- `SectionLibrary.tsx` (trong `builder/`): `<aside aria-label="Thư viện section">`, mỗi nhóm `<h3>`; mỗi type một thẻ `button`
  "Thêm <nhãn>" (thumbnail variant đầu theo `thumbnailSrc(themeId, …)`), nút `aria-expanded` "Kiểu của <nhãn>" mở lưới variant,
  mỗi variant là `button` "Thêm <nhãn> kiểu <variant>". Không phải `ok` → `disabled` + lý do qua `aria-describedby`, thẻ
  khóa có nhãn "Khóa theo gói". `!canReorder` → thư viện chỉ xem (mọi nút disabled, một dòng lý do quyền/gói).
- Kéo: `DndContext` bọc thư viện + sân khấu; chỉ `MouseSensor` (`distance: 4`) → bấm vẫn là click, chạm/bàn phím dùng click,
  không chặn cuộn cảm ứng. `useDroppable("canvas")` trên `DeviceStage`. Khi kéo: iframe `pointer-events-none` (nếu không iframe
  nuốt pointermove). `onDragMove` trên canvas: `y = (activator.clientY + delta.y − iframeRect.top) / (iframeRect.width / width)`
  → `post(drag)`; rời canvas → `drag-cancel` một lần. `onDragEnd` trên canvas → `pending.current = { type, variant }`, `post(drop)`;
  sự kiện `insert` chỉ được dùng khi có `pending` (rồi xóa) → thông điệp `insert` không mời bị bỏ qua. `DragOverlay` hiện thẻ.
- `addSection(type, variant, target?)`: chặn khi `!canReorder || conflict || changing`; `libraryStatus` khác `ok` → `setError(reason)`,
  không ghi; mặc định chèn sau section đang chọn, không có thì cuối. Cập nhật danh sách trước → `queue.write(saveSectionsDraft)`;
  lỗi → hoàn nguyên + `resultError` (thông điệp server); thành công → `forms[id] = { data: defaults, recovered: false }`,
  `refresh()`, rồi `choose(id)` (flush form cũ trước khi đổi) → không mất nháp form đang sửa.
- Bố cục: `xl:grid-cols-[16rem_minmax(0,1fr)_20rem]`, dưới `xl` thư viện nằm trên canvas, cao tối đa + cuộn riêng. Sửa câu hướng
  dẫn và trạng thái trống (không còn "Thêm section từ bố cục trang").

**Thumbnail CI** (workflow riêng để không kéo 32 shard matrix): `.github/workflows/thumbnails.yml`, PR + push base +
dispatch; job `changes` chạy `checks-map.mjs --github-output`; job `thumbnails` (ubuntu-24.04) khi `thumbnails == true`: cài, build
web, `LAB_ENABLED=true pnpm --filter web start --port 3210` + chờ, `THUMBNAILS_BASE_URL=… pnpm --filter @solar/visual thumbnails`,
rồi `git status --porcelain` trên `apps/admin/public/section-thumbs` + manifest: dòng khác ` M *.webp` (thêm/xóa/manifest) →
`::error::` kèm lệnh tải; chỉ ` M` → `::notice::` số ảnh lệch. Luôn upload artifact `section-thumbs` (2 đường dẫn, gốc repo).
`checks-map.mjs`: bộ `thumbnails` = paths/except của `matrix` + `tooling/visual/thumbnails.mts`, `apps/admin/public/section-thumbs/`,
`packages/cms-ui/src/sections/thumbnails`, `.github/workflows/thumbnails.yml`. README tooling/visual: `gh run download <id> -n section-thumbs -D .`.
