# Plan E12-S06 — Lịch sử, undo/redo, phiên bản

## Mục tiêu
Builder có hoàn tác/làm lại trong phiên (≥ 50 bước); trang có danh sách phiên bản đã xuất bản và khôi phục một phiên bản
vào bản nháp; hai người/tab mở cùng trang thấy cảnh báo (khóa mềm) và lần lưu cũ bị chặn thay vì ghi đè.

## Bối cảnh đã khảo sát
- `packages/db/src/publish.ts`: `publishPage` đã ghi `PageVersion { revision, snapshot: { sections, contents[] } }`
  (`contents`: `{ sectionId, type, schemaVersion, data }`). `lockPage` = khóa lạc quan theo `Page.revision`
  (`RevisionConflictError` khi `expectedRevision` cũ). `saveDraft` / `markRemoved` / `checkStructure` dùng lại được.
- `apps/admin/src/lib/pageSections.ts`: `loadPageEditor`, `loadBuilder`, `createPageSectionHandlers` (save, saveContent,
  publish…), `mutation()` map 409/400. `builderQueue.ts`: hàng đợi ghi tuần tự, 409 → khóa `conflict`.
- `Builder.tsx`: 3 thao tác cấu trúc (`reorder`, `addSection`, `changeLayout`) ghi `saveSectionsDraft`; nội dung ghi qua
  `BuilderPanel` (`useAutosave`, `flush()`), sửa inline đi qua `forms` rồi autosave.
- `PageSectionsEditor.tsx` (trang `/trang/[pageId]`) có nút Xuất bản; builder không có.
- Seed demo (`seed-demo.ts:77`) tạo `PageVersion` revision 1. Không có Redis bắt buộc (`runtime.redis` tùy chọn).
- Truy vấn: `codegraph` CLI không có trên PATH Bash phiên này (MCP lỗi kết nối) → khảo sát bằng grep `PageVersion|revision`,
  `publishPage|saveDraft`; Codex chạy `codegraph impact publishPage saveDraft createPageSectionHandlers loadPageEditor`.

## Thiết kế
1. **DB `restorePageVersion(db, tenantId, { pageId, versionId, expectedRevision, actor })`** trong `publish.ts`, export từ
   `@solar/db`. Trong một transaction: đọc version `{ id: versionId, pageId }` qua repo (tenant-scoped) **trước** `lockPage`
   — không có → `StructureError("Không tìm thấy phiên bản")`; parse snapshot bằng `restoreSnapshotSchema`; `lockPage`;
   `checkStructure` trên `descriptors(snapshot.sections)` (gói đã mất tính năng → `StructureError`, ngăn khôi phục vượt gói);
   `draftSections = sections`. Mỗi content của snapshot: `def` thiếu → StructureError; `data =
   def.schema.parse(migrateSectionData(def, c.schemaVersion, c.data).data)` (lỗi → `StructureError("Phiên bản có nội dung
   không còn hợp lệ, không thể khôi phục.")`); row cùng `sectionId`: khác `type` → StructureError; `row.schemaVersion !==
   def.schemaVersion` → StructureError("Nội dung cần cập nhật phiên bản trước khi khôi phục") (cùng luật `saveContent`, tránh
   publish migrate draft hai lần); có row → `update { draftData: data, revision: +1 }`; không có (đã dọn) → `create {
   schemaVersion: def.schemaVersion, data: def.defaults, draftData: data }`. Section trong snapshot không có content →
   `draftData = def.defaults`. Cuối `markRemoved` (section hiện có nhưng không có trong snapshot → removedAt, còn phục hồi
   30 ngày). **Chỉ ghi nháp**, không publish: người dùng xem trước rồi Xuất bản → sinh version mới (lịch sử không bị viết lại).
   Trả `{ revision }`.
2. **Admin**: `deps.versions(siteId, pageId)` → 20 bản mới nhất `{ id, revision, createdAt, publisher }` (`publisher` = tên
   SiteUser / "Quản trị nền tảng" / "Không rõ"). `loadPageEditor` thêm `versions` và `canRestore = pages.publish &&
   pages.structure && content.edit`. Handler `restore({ pageId, revision, versionId: z.uuid() })`: `ownPage` → kiểm 3 quyền
   (thiếu → 403) → `actor` → `mutation(() => deps.restore(...))`. Action `restorePageVersion = action("pages.publish", …)`.
3. **UI phiên bản** (`PageSectionsEditor`): `<section aria-label="Lịch sử xuất bản">`, mỗi dòng "Phiên bản {revision} ·
   {giờ vi-VN} · {publisher}" + nút "Khôi phục" (`aria-label="Khôi phục phiên bản {revision}"`, disabled khi `dirty`/pending/
   conflict). Bấm → xác nhận tại chỗ: "Bản nháp hiện tại sẽ được thay bằng phiên bản {n}." + "Xác nhận khôi phục" / "Hủy"
   (thao tác phá nháp cần xác nhận). Thành công → `router.refresh()` (editor key theo revision nên remount với nháp mới).
4. **Undo/redo** — `apps/admin/src/lib/builderHistory.ts` (thuần, không React):
   ```ts
   export const HISTORY_LIMIT = 100;
   export type HistoryStep = { kind: "sections"; before: EditableSection[]; after: EditableSection[] }
     | { kind: "content"; sectionId: string; before: unknown; after: unknown };
   export type History = { past: HistoryStep[]; future: HistoryStep[] };
   export const emptyHistory: History;
   export function record(h: History, step: HistoryStep): History; // bỏ no-op (JSON bằng nhau), cắt cũ nhất, xóa future
   export async function travel(h: History, dir: "undo" | "redo", apply: (step: HistoryStep, target: unknown) => Promise<{ ok: boolean }>): Promise<History>;
   export function historyShortcut(e: Pick<KeyboardEvent, "key" | "ctrlKey" | "metaKey" | "shiftKey" | "target">): "undo" | "redo" | null;
   ```
   `travel` chỉ di chuyển bước khi `apply` ok → ghi lỗi (409/400/mạng) không làm lệch lịch sử so với DB.
   Builder: `history` giữ trong ref + state (ref để `flush()` vừa ghi bước mới thì `travel` thấy ngay). `reorder`/
   `addSection`/`changeLayout` thành công → `record({ kind: "sections", before: previous, after: next })`. `save` của
   BuilderPanel thành công → `record({ kind: "content", sectionId, before: lastSaved[id], after: data })`, `lastSaved` (ref,
   khởi tạo từ `editor.forms`). Hoàn tác: chặn khi `busy/conflict/changing`; `panel.flush()` trước (lỗi → báo, dừng); áp
   bước qua `queue.write` (cùng action `saveSectionsDraft`/`saveSectionContent`, nên quyền và validate server giữ nguyên).
   Sections: `setSections(target)`, `latest.current.sections`, selected không còn → section đầu, `refresh()`. Content:
   `setForms`, `lastSaved[id] = target`, chọn section đó, tăng `panelNonce` (key `BuilderPanel` = `${id}:${nonce}`) để
   `useAutosave` khởi tạo lại với giá trị mới — **không** để autosave thấy thay đổi rồi ghi lại lần nữa (sinh bước thừa).
   Nút "Hoàn tác"/"Làm lại" ở header (`aria-keyshortcuts="Control+Z"` / `"Control+Shift+Z"`), disabled khi rỗng/bận/xung đột.
   Phím: `keydown` trên `window`; `historyShortcut` bỏ qua khi target nằm trong `input, textarea, select, [contenteditable]`
   (giữ undo gõ chữ của trình duyệt); Ctrl/⌘+Z, Ctrl/⌘+Shift+Z, Ctrl+Y. Phím trong iframe không lên cửa sổ admin — đúng ý.
5. **Khóa mềm** — `apps/admin/src/lib/editPresence.ts`: `createPresence({ ttl = 60_000, now })` bộ nhớ trong tiến trình
   (`globalThis` để HMR không mất), khóa `tenant:<tenantId>:page:<pageId>`, `touch(key, clientId, { accountId, name })` →
   danh sách người khác còn hạn (bỏ chính `clientId`, dọn bản hết hạn); cùng `accountId` → tên "Bạn (tab khác)".
   Quyết định: không dùng Redis/DB — đây là cảnh báo, không phải khóa cứng; xung đột thật đã chặn bằng revision; admin chạy
   một tiến trình. Ghi giới hạn vào README `apps/admin` mục builder. Handler `presence({ pageId, clientId: z.uuid() })` cần
   `pages.view` + `can("builder")` + `ownPage`; trả `{ ok, editors: string[] }` (thêm `editors?` vào `PageSectionResult`).
   Builder: `clientId = crypto.randomUUID()` (useState), gọi ngay và mỗi 20 s; `editors.length` → `<p role="status">`
   "{tên} cũng đang mở trình dựng trang này. Lần lưu đến sau sẽ bị từ chối nếu trang đã đổi — nên để một người sửa." Lỗi
   gọi presence → bỏ qua im lặng (không chặn sửa).
6. **AC2 phía UI**: giữ hành vi hiện có (409 → `conflict`, form giữ giá trị chưa lưu, `useLeaveGuard` vẫn cảnh báo khi tải
   lại vì `dirty`); thêm vào thông báo xung đột: "Nội dung bạn vừa sửa chưa được lưu." Không tự gộp/ghi đè.
